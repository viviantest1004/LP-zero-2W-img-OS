# 초기화와 공장 초기화

`apps-and-settings.md` §5 에 신설하는 항목이고, `panes/s-reset` 과
`panes/factory-zone` 이 그린 화면의 명세다. 그 문서의 §5-1 부터 §5-19
까지는 설정을 **바꾸는** 방법을 적었고, 바꾼 것을 **되돌리는** 방법은
한 줄도 없었다.

되돌리는 쪽이 더 어렵다. 바꾸는 것은 값 하나를 쓰면 끝나지만, 되돌리는
것은 "무엇이 처음 값인가"와 "무엇을 건드리면 안 되는가"를 둘 다 알아야
한다. 뒤엣것을 틀리면 사람의 파일이 사라진다.

| 무엇 | 어디 |
|---|---|
| 항목별 초기화 일곱 줄 | `design/gui/panes/s-reset.js` 의 `KINDS` |
| 공장 초기화 흐름 다섯 화면 | `panes/factory-zone.js`, `factory-zone.dialogs` |
| 누가 누를 수 있는가 | `lp-core.js` 의 `LP.can()`, `LP.allow.reset` / `LP.allow.factory` |
| 디스크 루트가 어떻게 뜨는가 | `userland/preinit/preinit.c`, `tools/mkdisk.sh` |
| 램 루트가 무엇을 `/data` 에 남기는가 | `userland/persist/persist.c`, `boot/rootfs-overlay/etc/rc` |
| 초기화해도 남아야 하는 키 | `userland/authkey/authkey.c` |

**적용 범위**: 화면은 amd64 데스크탑 전용이다. 파이 Zero 2 W 는 이
설정 앱을 띄우지 않는다. 그래도 공장 초기화는 필요하고, 거기서는 화면이
아니라 명령이다 — §5.

---

## 1. 하나의 원칙이 나머지를 전부 정한다

> **초기화는 설정을 되돌린다. 사람이 만든 것은 건드리지 않는다.**

이 문장이 목록에 무엇이 들어가고 무엇이 빠지는지를 혼자 결정한다. 그래서
모든 줄은 두 문장으로 설명할 수 있어야 한다.

```
무엇이 돌아오는가
무엇이 남는가
```

**두 번째 문장을 쓸 수 없는 항목은 이 화면에 있으면 안 된다.** 되돌아오는
것만 적고 남는 것을 적지 않으면, 사람은 눌러 봐야 알게 된다. 눌러 봐야
아는 버튼은 안 눌리는 버튼이고, 안 눌리는 초기화 버튼의 대안은 재설치다.

화면 맨 위에 한 번 적고 일곱 줄에 반복하지 않는다. 모든 줄에 답이 같은
유일한 질문이기 때문이다.

> 어느 항목을 초기화해도 문서와 사진, 내려받은 파일, 설치한 앱은
> 지워지지 않습니다. 설정만 돌아갑니다.

### 1-1. 목록에 넣지 않은 것

전부 "되돌린다"는 말이 어울리는 동작이고, 전부 위 문장을 쓸 수 없어서
빠졌다.

| 넣지 않은 것 | 왜 |
|---|---|
| 휴지통 비우기 | 사람이 만든 것을 지운다. 되돌아오는 것이 없다. `§5-14 저장 공간` |
| 캐시 정리 | 지우기만 하고 아무것도 돌아오지 않는다. 정비이지 초기화가 아니다. `§5-14` |
| 설치한 앱 지우기 | 설치는 설정이 아니라 결정이다. `§5-13`, 소프트웨어 센터 |
| 방문 기록·검색 기록 지우기 | 기록은 사람이 남긴 것이다. 그래서 웹 줄이 지우지 않는다 |
| 계정 초기화 | 그런 것은 없다. 계정을 지우는 것은 `§5-12 사용자` 다 |
| 설정 앱 초기화 | 설정 앱에는 자기 상태가 없다. 되돌릴 것이 없다 |

이 여섯 개를 여기 넣으면 화면 위의 한 문장이 거짓이 되고, 한 문장이
거짓이면 나머지 여섯 줄도 못 믿게 된다.

### 1-2. 경계에 걸린 하나 — 사용자 지정 단축키

`단축키` 초기화는 직접 만든 단축키를 지운다. 그건 사람이 만든 것이다.

그래도 남긴다. 원칙이 지키려는 것은 **여기서만 존재하고 다시 만들 수
없는 것** — 문서, 사진, 내려받은 파일 — 이고, 사용자 지정 단축키는
`Super+K`와 명령 한 줄이다. 게다가 단축키 목록을 처음 값으로 되돌리면서
목록에 나중에 더한 것만 남길 방법이 없다. 목록의 "처음 값"은 출고
목록이다.

그래서 숨기지 않고 줄 설명에 그대로 적는다.

> 모든 단축키가 처음 값으로 돌아가고, 직접 만든 단축키는 지워집니다

이 한 줄이 §3 의 비밀번호 규칙이 왜 그런지도 같이 설명한다. 지워진
단축키를 되찾는 방법은 다시 만드는 것이고, **다시 해서 되돌아오는 것에는
비밀번호를 받지 않는다.**

## 2. 일곱 줄

여섯 개의 항목별 초기화와, 그 여섯을 한 번에 하는 `모든 설정`.

| 항목 | 돌아오는 것 | 남는 것 |
|---|---|---|
| 단축키 | 단축키 표 전부 | 입력 소스, 입력 전환 키 |
| 키보드 설정 | 입력 소스, 전환 키, 키 반복 속도·시작 지연 | 단축키. **English (US)** |
| 화면 | 해상도·주사율, 배율, 방향, 야간 모드 | 배경 화면 |
| 소리 | 출력·입력 볼륨, 앱별 볼륨, 알림음 | 골라 둔 출력·입력 장치 |
| 네트워크 | — (지운다) 저장된 Wi-Fi 와 비밀번호, 고정 주소, 프록시, VPN | 파일, 계정, 다른 설정 |
| 웹 | 홈페이지, 검색 엔진, 사이트 권한, 쿠키, 캐시 | **즐겨찾기, 저장한 비밀번호, 방문 기록** |
| 모든 설정 | 위 여섯 개 전부 | 계정과 로그인 비밀번호, 문서와 사진, 설치한 앱 |

**한 항목마다 놀라는 지점이 하나씩 있다.** 그 지점이 그 줄의 설명이 존재
하는 이유이고, 설명이 짧아지면 제일 먼저 잘려 나가는 부분이다.

### 2-1. 네트워크 — 이 컴퓨터가 네트워크에서 떨어진다

저장된 Wi-Fi 를 지운다는 것은 **지금 붙어 있는 Wi-Fi 도 지운다**는
뜻이다. 초기화가 끝나는 순간 연결이 끊어진다.

그리고 다시 붙으려면 Wi-Fi 비밀번호를 입력해야 하는데, **그 비밀번호는
방금 지운 것이다.** 집 공유기 비밀번호를 외우는 사람은 드물다. 기억하는
사람이 아무도 없으면 그 기계는 누가 종이를 찾아낼 때까지 네트워크 밖에
있다.

그래서 이 줄과 `모든 설정` 만 앰버 경고를 단다.

> ▲ 초기화하면 이 컴퓨터가 네트워크에서 떨어집니다. 다시 연결하려면
> Wi-Fi 비밀번호를 한 번 더 입력해야 합니다.

**앰버이고 빨강이 아니다.** `shell-design-spec.md` §1-3 이 정한 대로,
앰버는 지금 이 기계가 할 수 있는 일에 걸린 제약이고 빨강은 실패다. 빨강을
칠하면 초기화가 잘못됐다는 뜻이 된다.

### 2-2. 웹 — 즐겨찾기와 비밀번호는 그대로다

이 줄을 누르기 전에 사람이 알고 싶은 것은 정확히 하나다. **즐겨찾기와
저장한 비밀번호도 같이 가는가.** 안 간다.

대신 쿠키가 간다. 그래서 로그인해 둔 사이트에서는 전부 로그아웃된다.
"지워지지 않는다"와 "로그아웃된다"는 같이 적어야 한다. 앞엣것만 적으면
다음 날 아침에 놀라고, 뒤엣것만 적으면 아무도 안 누른다.

**아직 정하지 않은 것**: 이 줄이 건드리는 것은 우리 프로그램이 아니다.
브라우저는 `apt` 로 가져온 Firefox 이고(`apps-and-settings.md` §3-1),
설정은 그 프로필 디렉터리 안에 있다. 남의 프로필을 편집하는 것과 브라우저
자신에게 시키는 것 사이에서 아직 고르지 않았다. 편집하는 쪽은 버전이
올라갈 때마다 깨지고, 시키는 쪽은 시킬 방법이 없다.

### 2-3. 화면 — 되돌릴 숫자를 저장해 두지 않는다

해상도와 주사율의 "처음 값"은 저장해 둔 숫자가 아니라 **연결된 화면에게
다시 물어본 값**이다. 이게 중요한 이유는 모니터가 바뀌기 때문이다.
출고 시의 1920×1080 을 기억해 두었다가 4K 모니터에 다시 씌우면 초기화가
화면을 망가뜨린 것이 된다.

배경 화면은 건드리지 않는다. 이 화면에서 사람이 고른 파일에 가장 가까운
것이고, `§5-7 모양` 에 속한다.

### 2-4. 소리 — 장치는 그대로 둔다

볼륨과 앱별 볼륨은 되돌리고, 골라 둔 출력·입력 장치는 그대로 둔다.

장치를 같이 되돌리면 소리가 다른 데서 나기 시작하고, 사람은 볼륨 키를
누르며 소리가 나지 않는 장치의 볼륨을 올린다. **조용한 실패이고, 초기화가
소리를 고장 낸 것처럼 보인다.**

### 2-5. 키보드 — English (US) 는 초기화해도 남는다

`lp-core.js` 의 `canRemoveSource()` 가 지키는 규칙이 초기화에도 그대로
적용된다. 키보드에 인쇄된 글자, 로그인 화면의 비밀번호 입력, 복구 콘솔이
전부 이 배열을 쓴다. 한국어만 남은 기계는 `fsck` 를 칠 수 없는 기계다.
자세한 것은 `input-sources.md`.

### 2-6. 모든 설정 — 공장 초기화가 아니다

목록의 일곱째 줄이 아니라 `전체` 라는 별도 구역에 있다. 여섯 개를 훑던
눈이 일곱째에서 우연히 멈추는 일이 없어야 한다.

그리고 **공장 초기화가 아니라는 말을 두 번 한다** — 줄 설명에 한 번,
확인 대화상자에 한 번. 버튼 아래 작은 글씨로 적지 않는다. 버튼 아래까지
간 사람은 이미 결정한 사람이다.

구현은 여섯 개를 차례로 부르는 것이고, 무엇을 되돌리는지 다시 적지
않는다. 같은 목록이 두 군데 있으면 한쪽이 뒤처지고, 뒤처진 쪽은 아무도
안 읽는 쪽이다.

## 3. 확인은 전부 받고, 비밀번호는 하나도 받지 않는다

### 3-1. 왜 전부 확인을 받는가

일곱 개의 버튼이 세로로 붙어 있고 이름은 전부 두세 글자다. `화면` 과
`소리` 사이는 한 줄이다. **이 화면이 잘못되는 정상적인 방법은 마음이
바뀌는 것이 아니라 한 줄 잘못 누르는 것이다.**

확인 대화상자는 "정말입니까"를 묻는 물건이 아니라 **방금 누른 것이 무엇인지
읽을 기회**다. 그래서 대화상자에는 §2 의 두 문장이 그대로 들어간다.
줄 설명과 대화상자 문구는 모듈 안의 한 표에서 나오므로 서로 다른 말을 할
수 없다.

### 3-2. 왜 비밀번호는 받지 않는가

기준은 하나다.

> **같은 일을 다시 해서 되돌아오는가.**

일곱 개 전부 그렇다. 단축키는 다시 지정하면 되고, Wi-Fi 는 비밀번호를
다시 넣으면 되고, 볼륨은 다시 맞추면 된다. 시간이 들 뿐 잃은 것이 없다.

비밀번호는 "다른 사람이 이걸 하는 것"을 막는 장치이고, 그 질문의 답은
이 화면이 아니라 계정 모델에 있다. `LP.allow.reset` 은 기본값이 `false`
이므로 표준 계정에게는 일곱 줄 전부가 잠겨 있고, 잠긴 줄은 누구에게
말해야 하는지를 같이 보여 준다.

> 관리자만 바꿀 수 있습니다

그리고 비밀번호를 일곱 번 받으면 **여덟 번째가 싸진다.** 사람은 읽지 않고
치는 법을 배우고, 여덟 번째는 공장 초기화다. 여기서의 절제는 예의가
아니라 마지막 하나를 비싸게 유지하는 방법이다.

### 3-3. 공장 초기화는 둘 다 받는다

비밀번호와, 손으로 친 문구 `초기화`.

**둘은 다른 질문이다.**

| 묻는 것 | 답하는 것 |
|---|---|
| 관리자 비밀번호 | **누구인가** |
| `초기화` 라고 입력 | **그럴 뜻이었는가** |

비밀번호 하나로는 앞엣것밖에 답하지 못한다. 사람은 하루에 자기 비밀번호를
여러 번 반사적으로 친다. 문구는 반사적으로 칠 수 없고, 치는 동안 위의
문장을 읽게 된다. 그래서 공백을 다듬지 않고 **친 그대로 비교한다** —
다듬으면 사람이 쓰지 않은 것을 조용히 받아들이는 것이다.

표준 계정에게는 `LP.can('factory')` 가 언제나 `false` 다. 관리자가
`사용자 › 권한` 에서 넘겨줄 수 있는 항목이 아니다. 넘겨줄 수 있게 하면
"관리자만" 이라는 문장이 설정 가능한 기본값이 된다.

### 3-4. 순서 — 사실, 비밀번호, 문구

기계가 원하는 순서는 비밀번호가 먼저다. 사람에게는 틀린 순서다.

**비밀번호를 친 사람은 이미 결정한 사람이다.** 마음을 바꿨을 문장이
결정 다음에 도착하면 그건 읽는 글이 아니라 넘기는 화면이다. 그래서 첫
화면에는 입력란이 아예 없다. 지워지는 것 여섯 줄과 남는 것 두 줄, 그리고
전원을 끄면 안 된다는 한 줄뿐이다.

다섯 화면 전부 답하지 않고 나갈 수 있다 — `취소`, 바깥쪽 클릭, `Esc`.
**나갈 수 없는 확인은 확인이 아니라 함정이다.** 진행 중 화면만 `취소`
버튼이 없는데, 그건 그 시점에 취소할 것이 없기 때문이고, 하지 못하는 일을
적은 버튼은 없는 것보다 나쁘다.

## 4. 공장 초기화 — 데스크탑

여기가 두 기계가 갈라지는 곳이고, 이 문서에서 가장 정해지지 않은
부분이다.

### 4-1. 되돌릴 원본이 없다

파이 이미지에서는 시스템 전체가 커널 이미지 안의 cpio 다. 부팅할 때마다
램으로 풀리므로 **모든 부팅이 이미 출고 상태다.** 디스크 위의 어떤 것도
돌아가는 시스템의 일부가 아니다.

데스크탑은 반대다. `preinit` 이 `LPROOT` 라벨이 붙은 ext4 파티션을 찾아
마운트하고 그리로 `switch_root` 한 다음, 그 위의 `/sbin/init` 에 넘긴다.
커널 안의 initramfs 에는 `preinit` 하나뿐이고 크기는 30KB 남짓이다.
`/etc` 가 내일도 있고, 패키지가 오버레이가 아니라 진짜 `/usr` 로 들어가고,
루트가 램보다 클 수 있는 것이 전부 이 구조에서 나온다.

그 대가가 이것이다. **원본이 없다.** 무언가가 시스템을 다시 갖다 놓아야
하고, 그 무언가를 어디에 둘지는 아직 정해지지 않았다.

### 4-2. 세 가지 길

| | 디스크 비용 | 되돌리지 못하는 것 |
|---|---|---|
| **A. 원본 사본을 따로 둔다** | 기본 시스템 크기만큼 한 번 | 디스크 자체의 고장, 원본 파티션까지 덮어쓴 경우 |
| **B. 설치 관리자를 다시 돌린다** | A 와 같음 (원본은 여전히 필요) | A 와 같음. 그리고 **설치 관리자가 없다** |
| **C. btrfs 서브볼륨 스냅샷** | 처음엔 0, 갈라지는 만큼 증가 | **파일 시스템이 안 열리는 경우 전부.** 스냅샷은 자기가 찍은 파일 시스템 안에 있다 |

**A — 원본 사본.** 빌드할 때 만든 기본 시스템을 그대로 한 벌 더 넣어
두고, 초기화는 그것을 루트에 다시 쓴다. 어디에 두느냐가 다시 둘로
갈린다.

*ESP 위에*: 지금은 공짜다. ESP 는 256MB 이고, `preinit` 만 들어간 커널은
몇 MB 라 250MB 가까이 비어 있다. 현재 `userland/rootfs-amd64` 는 9.2MB
이므로 스무 벌도 들어간다. **그런데 지금 그렇다는 것이 함정이다.**
데스크탑이 올라가면(§3-1 의 기본 탑재 앱, Firefox 혼자 약 250MB) 기본
시스템은 수백 MB 가 되고 ESP 는 그날 부족해진다. 오늘 되고 이미지가
데스크탑이 되는 순간 안 되는 설계다. 게다가 ESP 는 사람이 카드 리더로
열어서 파일을 넣고 빼는 파티션이다. `authorized_keys` 옆에 수백 MB 짜리
복구본을 두면 자리를 비우려고 지워진다.

*세 번째 파티션에*: ext4, 라벨 `LPBASE`, 빌드할 때 한 번 쓰고 그 뒤로는
읽기 전용. **돌아가는 시스템이 마운트하지도 않는 파티션이고, 마운트되지
않은 파티션은 돌아가는 시스템이 망가뜨릴 수 없다.** 이것이 ESP 대비 가장
큰 차이다. ext4 라서 저널이 있고, 이미 싣고 다니는 `e2fsck` 로 고칠 수
있다. FAT32 의 4GB 파일 크기 상한도 없다.

**B — 설치 관리자.** `shell-design-spec.md` §7 이 `amd64 설치 관리자
(calamares 검토)` 를 미결로 적어 두었고, 저장소에는 없다. `mkdisk.sh` 는
빌드 기계에서 `mkfs.ext4 -d` 로 루트를 통째로 만든다 — 대상 기계에서
도는 코드가 아니다. 그리고 설치 관리자도 어딘가에서 파일을 읽어야 하므로
**A 에 프로그램을 하나 더한 것**이지 A 의 대안이 아니다. 다만 이 일은
언젠가 해야 한다. dd 로 굽는 것 말고 내장 디스크에 설치하는 길이 필요해
지는 날, 그 프로그램이 공장 초기화도 같이 답한다.

**C — btrfs 스냅샷.** 첫 부팅에 스냅샷을 하나 찍어 두고 초기화는 거기로
되돌린다. 공간을 거의 쓰지 않고, 이 세 개 중 유일하게 **"어제로 돌아가기"**
까지 준다.

그런데 이 프로젝트에서는 설정 하나가 아니라 루트 파일 시스템 교체다.
`kernel/lp-zero-amd64.config` 에 `CONFIG_BTRFS_FS=n` 이 명시적으로 적혀
있고, `preinit.c` 는 `lp_mount(dev, NEWROOT, "ext4", ...)` 로 파일 시스템
종류를 박아 두었고, 기계에 실려 있는 파일 시스템 도구는 `e2fsck` 와
`mke2fs` 둘뿐이다(둘 다 ext2/3/4 전용, 부팅 파티션에 놓여 있고 커널
이미지 안의 해시로 검증된다). 커널도 1MB 넘게 커진다.

**그리고 결정적인 것**: 스냅샷은 자기가 찍은 파일 시스템 안에 산다.
루트가 안 열리는 상황 — 공장 초기화를 하고 싶어지는 상황의 큰 몫 — 에서
스냅샷도 같이 안 열린다. 다른 파티션 위의 사본은 그걸 넘긴다.

### 4-3. 권장 — 세 번째 파티션 위의 원본 이미지

```
p1  FAT32  LPZERO   256MB   ESP — 커널, cmdline.txt, authorized_keys,
                              wpa_supplicant.conf, firewall.conf,
                              beacon.conf, e2fsck, mke2fs
p2  ext4   LPBASE   기본 시스템 크기 + 여유 — 읽기 전용, base.img
p3  ext4   LPROOT   나머지 전부 — 진짜 루트
```

`LPBASE` 에는 **파일 시스템 이미지 하나**를 둔다. tar 가 아니라 이미지인
이유가 셋이다.

1. **`dd` 와 `expandfs` 는 이미 있고 이미 매 첫 부팅에 돌고 있다.**
   새로 쓸 코드가 없다. `expandfs` 는 `EXT4_IOC_RESIZE_FS` 로 마운트된
   ext4 를 늘리고, 늘리기만 하며 줄이는 경로가 아예 없다.
2. **복구한 루트와 갓 구운 루트가 같은 바이트다.** 빌드 기계의
   `mkfs.ext4` 가 만든 그 파일 시스템이 그대로 돌아온다. 시험할 상태가
   둘이 아니라 하나다.
3. tar 로 하면 모드·시간·심볼릭 링크를 우리 `tar` 가 전부 옳게
   되돌려야 한다. **몇 달 뒤에 파일 하나에서 드러나는 종류의 버그다.**
   (여기서 한 가지는 공짜다. 이 시스템은 사용자가 root 하나뿐이라 모든
   파일이 uid 0 이고, 소유권 문제가 없다.)

압축하지 않는다. **이 유저랜드에는 압축 해제기가 없다.** `tar.c` 가
그렇게 적어 두었다 — 유일한 압축 해제기는 커널 안에 있고 거기서 부를 수
없다. 이미지의 빈 곳은 0 이므로 굽는 시간은 낭비되지만, 그건 초기화할 때
한 번이다.

원본의 SHA-256 은 **`preinit` 안에 컴파일해 넣는다.** `cmdline.txt` 에
적으면 ESP 를 만질 수 있는 사람이 바꿀 수 있고, `update` 의 서명 공개키를
커널 이미지 안에 둔 것과 같은 이유로 그건 약하다. `mkdisk.sh` 가 원본
이미지와 커널을 같은 스크립트에서 만드니 순환도 생기지 않는다. 해시
검사는 초기화할 때만 한다 — 매 부팅마다 수백 MB 를 읽을 이유가 없다.

**비용을 정직하게**: 기본 시스템 하나만큼의 디스크. 오늘은 9.2MB 이고
데스크탑이 올라가면 수백 MB 다. `mkdisk.sh` 의 기본 `SIZE_GB=4` 짜리
이미지에서는 10% 가까이 되고, 128GB SSD 에서는 눈에 띄지 않는다. **고정
비용이라 작은 디스크에서만 아프다.** 복구 수단으로서는 맞는 모양이다.

### 4-4. 어떻게 되돌리는가 — 그리고 진행 막대는 이 창에 없다

**초기화는 자기가 지울 루트 위에서 돌 수 없다.** 마운트된 루트의 블록
장치에 덮어쓰면 돌아가는 시스템이 그 순간 부서진다. 그러니 재부팅해야
하고, 되돌리는 일은 루트가 아직 없는 시점에 있는 프로그램이 해야 한다.
그 프로그램이 이미 있다. `preinit` 이다.

```
1. 설정 앱: LPBASE 를 확인하고 base.img 의 해시를 검사한다
     ─ 여기까지 아무것도 지우지 않는다. 전원이 나가도 잃은 것이 없다
2. 설정 앱: LPBASE 를 잠깐 쓰기 가능으로 열어 표식 파일을 쓰고 닫는다
3. 재부팅
4. preinit: 표식을 보고 base.img 를 LPROOT 에 dd, sync, 표식을 지운다
5. preinit: 평소 하던 일 — LPROOT 를 찾아 마운트하고 switch_root
6. /etc/rc: expandfs 가 새 루트를 파티션 끝까지 늘린다 (첫 부팅과 같다)
7. /etc/rc: authkey 가 ESP 의 인증 키를 다시 합쳐 넣는다
```

**결과 하나가 목업과 다르다.** `factory-zone.dialogs` 의 진행 화면은
설정 창 안의 대화상자이고 다섯 단계를 막대로 보여 준다. 4단계가 재부팅
뒤에 일어나므로 **그 창은 그때 존재하지 않는다.** 설정 앱이 마지막으로
정직하게 말할 수 있는 것은 여기까지다.

> 이 컴퓨터가 곧 다시 시작합니다.

진행 표시는 부팅 화면에 속하고, 그리는 것은 `splash` 다. 목업의 다섯
단계 문구도 같이 바뀐다 — `부팅 파티션의 사본` 은 `복구 파티션의 사본`
이 되고, `계정과 홈 폴더를 지웁니다` / `설치한 앱과 패키지를 지웁니다`
는 사실 별도 단계가 아니다. 파티션을 통째로 다시 쓰면 그 둘은 같은 한
번의 쓰기다.

### 4-5. 있는 것으로 만들 수 있는 것과, 새로 써야 하는 것

| 이미 있는 것 | 어디 |
|---|---|
| 라벨로 파티션 찾기, 나타날 때까지 기다리기 | `preinit.c` — 100ms × 50회, 20회째에 "아직 찾는 중" |
| 부팅 파티션의 프로그램을 해시 검사 후 실행 | `libc/src/disk.c` 의 `boot_tool()` |
| ext4 만들기·고치기 | `/boot` 의 `mke2fs`, `e2fsck` (`/etc/boot-tools.sha256` 로 검증) |
| 마운트된 ext4 를 파티션 끝까지 늘리기 | `expandfs` |
| 블록 복사 | `dd` |
| 부팅 화면 그리기 | `splash` |

| 새로 써야 하는 것 |
|---|
| `mkdisk.sh` 에 세 번째 파티션과 `base.img` 만들기 |
| `mkdisk.sh` 가 ESP 에 `e2fsck`·`mke2fs` 도 넣기 — **지금 안 넣는다.** `mksdcard.sh` 는 넣는다 |
| `preinit` 의 표식 확인, dd, 해시 검사 (`lp_sha256_file` 은 이미 libc 에 있다) |
| `expandfs` 가 파티션 번호 2 와 `/data` 에 박혀 있는 것을 인자로 받게 |
| 설정 앱에서 표식을 쓰는 경로 |

### 4-6. 돌아오는 것은 출고본이지 어제가 아니다

**공장 초기화는 출고 시점으로 되돌린다.** 그동안 받은 시스템 업데이트도
같이 없어지고, 초기화가 끝난 기계는 업데이트를 다시 받아야 한다.

이걸 적어 두는 이유는 §4-2 의 C 안이 이 지점에서만은 더 낫기 때문이다.
스냅샷은 "어제"를 줄 수 있고 원본 사본은 못 준다. **다만 "어제"가 필요한
문제와 "출고"가 필요한 문제는 다른 문제다.** 앞엣것은 업데이트 롤백이고,
파이 쪽에서는 `update --rollback` 과 `/boot/system-standby.img` 가 이미
답하고 있다.

데스크탑에는 그 답이 아직 없다. 시스템이 파일 하나가 아니게 된 순간
`update` 의 전제도 같이 깨졌다 — `update.c` 는 커널 이미지를 통째로
바꾸고 `/boot/EFI/BOOT/BOOTAA64.EFI` 라는 aarch64 이름이 박혀 있다.
**공장 초기화를 어렵게 만든 그 사실이 업데이트도 같이 어렵게 만들었고,
한쪽을 푸는 설계가 다른 쪽도 같이 풀어야 한다.** 미결로 남긴다.

## 5. 공장 초기화 — 램 루트 보드

파이 Zero 2 W 는 이 GUI 를 띄우지 않는다. 콘솔 셸을 그대로 쓴다. 그래도
공장 초기화는 필요하고, 누군가 반드시 묻는다.

**거기서는 거의 아무것도 아니다.** 시스템이 커널 이미지 안의 cpio 이고
매 부팅마다 이미 출고 상태이므로, 되돌릴 시스템이 없다. 데이터 파티션을
지우면 끝이다.

### 5-1. 이름 — `reset` 은 이미 있다

`userland/reset/reset.c` 는 **터미널을 정상으로 되돌리는 명령**이다.
`reset --factory` 는 쓸 수 없다.

권장: `datadisk --factory`. `datadisk` 는 이미 데이터 파티션이 어디
있는지 알고, 이미 `--format` 으로 디스크를 지우고 새 `/data` 를 만들고,
이미 `boot_tool("mke2fs")` 로 부팅 파티션의 도구를 해시 검사 후 부른다.
**있는 명령의 아홉 할이 이미 이 일이다.** 새 명령을 만들면 같은 코드가 두
벌이 된다.

**아직 없다.** 저장소에 공장 초기화를 하는 코드는 한 줄도 없다.

### 5-2. 지우는 것

`/data` 파티션 전체다. 그 안에 무엇이 있는지 알아야 이 문장이 뜻을
가진다.

| 무엇 | 왜 놀라는가 |
|---|---|
| `/data/persist` | **`/bin` `/sbin` `/lib` `/usr` `/opt` `/srv` 오버레이의 윗층.** `cp mytool /bin/` 이든 `make install` 이든, 시스템 안에 설치한 것이 전부 여기 있다. 사람들이 가장 자주 잊는 것 |
| `/data/etc` | `persist etc keep` 으로 남겨 둔 `/etc` 파일들 |
| `/data/root` | 홈 디렉터리. `/root` 에 bind 되어 있다. `.profile`, `.ssh/authorized_keys` |
| `/data/users`, `/data/groups` | `useradd` 로 만든 계정 |
| `/data/dropbear_ed25519_host_key` | **SSH 호스트 키.** 다음 접속에서 클라이언트가 "키가 바뀌었다"고 경고한다. 그건 맞는 경고다 — 바뀌었다 |
| `/data/log` | `logd` 의 로그, `auth` 의 로그인 기록, `status.json` |
| `/data/bin` `/data/pkg` `/data/python` `/data/debian` | `pkg`, `pip`, `apt` 로 설치한 전부. `apt` 트리 하나가 440MB 다 |
| `/data/rc.local`, `/data/services` | 부팅마다 돌던 것과 init 이 지키던 서비스 |
| `/data/firewall.conf`, `/data/beacon.conf`, `/data/wpa_supplicant.conf` | `/boot` 사본이 있으면 다음 부팅에 다시 온다 |
| `/data/.clock`, `/data/timezone`, `/data/.integrity`, `/data/boot_count` | 시계, 시간대, 해시 기록, 부팅 실패 카운터 |

### 5-3. 어떻게

두 가지가 있고, 둘째를 권한다.

**(a) 아는 경로를 지운다.** 간단하고, 돌고 있는 시스템 위에서 바로 된다.
문제는 **목록이 코드와 따로 관리된다**는 것이다. 내일 무언가가 `/data`
에 새 파일을 쓰기 시작하면 이 목록은 그날부터 틀렸고, 틀렸다는 신호가
없다.

**(b) 파티션을 다시 만든다.** `mke2fs` 한 번. 남는 것이 없고 목록도
없다. 카드가 닳으며 생긴 것들도 같이 간다.

문제는 **`/data` 를 언마운트할 수 없다**는 것이다. `/root` 가 거기서
bind 되어 있고, `logd` 가 쓰고 있고, 서비스들이 살아 있다. 그래서
데스크탑과 같은 모양이 된다.

```
1. /boot 를 잠깐 쓰기 가능으로 열어 표식을 쓰고 다시 읽기 전용
     ─ authkey 가 개인 키를 넣을 때 하는 그 동작 그대로
2. 재부팅
3. /etc/rc: /data 를 마운트하기 전에 표식을 보고 mke2fs, 표식을 지운다
4. 그 뒤는 첫 부팅과 완전히 같다
```

4단계가 공짜인 이유가 이 보드의 전부다. `rc` 의 모든 단계가 **"파일이
없다"를 이미 정상적인 첫 부팅으로 처리한다** — `mkdir -p /data/log`,
`persist on` 이 `/data/persist` 를 새로 만들고, `authkey` 가 `/boot` 와
이미지에서 키를 합쳐 넣고, `dropbearkey -y` 가 실패하면 호스트 키를 새로
만들고, `useradd --merge` 가 없는 파일을 조용히 넘긴다. **공장 초기화를
위해 새로 써야 하는 부팅 코드가 없다.**

**표식이 `/boot` 에 있다는 것의 뜻**: 카드 리더를 가진 사람이 파일 하나로
이 기계를 지울 수 있다. 새로 늘어난 능력은 아니다 — 카드를 가진 사람은
이미 카드를 새로 구울 수 있고, `/boot` 의 `authorized_keys` 와
`firewall.conf` 로 이미 이 기계 전체를 가질 수 있다. `rc` 가 라벨
`LPZERO` 를 확인하는 이유가 그것이다. 그래도 적어 둔다.

## 6. 두 기계에서 모두 살아남아야 하는 것 — SSH 인증 키

> **네트워크로만 닿는 기계의 초기화가 열쇠를 같이 가져가면, 그건 초기화가
> 아니라 폐기다.**

`authkey.c` 전체가 이 문장 하나를 위해 있다. 키는 세 군데에 있고 뒤로 갈
수록 지우기 어렵다.

| 어디 | 무엇 |
|---|---|
| `/root/.ssh/authorized_keys` | 살아 있는 것. **없어졌다고 가정한다** |
| `/boot/authorized_keys` | FAT32, 읽기 전용 마운트, 아무 PC 에서나 쓸 수 있다 |
| `/etc/authorized_keys` | 커널 이미지 안. 어떤 파일 시스템에서도 닿을 수 없다 |

매 부팅마다 바깥 둘을 안쪽으로 합친다. 그리고 **이미지 것과 부팅 파티션
것을 먼저 읽는다** — 살아 있는 파일은 `/data` 위에 있고, 그걸 쓸 수 있는
쪽이 `MAX_KEYS` 까지 채우면 지울 수 없다던 이미지 키가 조용히 제일 먼저
잘려 나가기 때문이다.

### 6-1. 데스크탑에서는 세 겹이 아니라 한 겹이다

**이 비대칭이 이 절이 존재하는 이유다.**

데스크탑에는 cpio 가 없다. `/etc/authorized_keys` 는 커널 안의 닿을 수
없는 사본이 아니라 **루트 위의 평범한 파일**이고, 공장 초기화가 루트를
다시 쓰면 같이 출고본으로 돌아간다. 출고본에는 키가 한 줄도 없다 —
주석뿐이다.

그래서 데스크탑에서 초기화를 넘겨 살아남는 인증 키는 **ESP 의 것 하나**다.
파이에서는 셋 중 둘이 자동으로 남지만, 데스크탑에서는 하나뿐이고 그
하나가 없으면 아무도 못 들어온다.

### 6-2. 그리고 지금 거기에 구멍이 하나 있다

`authkey new` 와 `authkey add` 는 **`/boot/authorized_keys` 에 쓰지
않는다.** 합치기는 한 방향이다 — 이미지와 부팅 파티션에서 살아 있는
파일로. `authkey new` 는 공개 키를 `/root/.ssh/authorized_keys` 에만
쓰고, `/boot` 에는 **개인** 키(`/boot/lp_ssh_key`)를 가져가라고 놓아 둘
뿐이다. 개인 키는 권한이 아니다. 아무도 그걸 읽지 않는다.

그러므로 지금 상태에서는:

- **데스크탑**: `authkey new` 로 만든 키는 공장 초기화에서 사라진다.
- **파이**: `authkey new` 로 만든 키는 `/data` 가 망가지면 사라진다.
  `authkey.c` 가 막으려고 존재하는 바로 그 상황인데, 하필 가장 쉬운
  경로로 들어온 키가 그 보호를 못 받는다.

**초기화 쪽에서 고치지 않는 것을 권한다.** 초기화가 지우기 전에 키를
`/boot` 로 복사하게 만들면, 그 약속은 초기화하는 순간에만 지켜진다.
`authkey new` 와 `authkey add` 가 `/boot/authorized_keys` 에도 쓰게
하면 **불변식이 계속 참이다** — "ESP 에는 로그인할 수 있는 키가 전부
있다". 그러면 디스크가 죽는 경우까지 같이 덮인다. `/boot` 를 잠깐 쓰기
가능으로 여는 코드는 `authkey.c` 에 이미 있다.

### 6-3. 그래서 공장 초기화는 "남에게 넘기기"가 아니다

초기화 화면은 이렇게 약속한다.

> 부팅 파티션의 SSH 인증 키는 남습니다

**네트워크로만 닿는 기계에는 이게 맞는 약속이다.** 동시에 이건 이전
주인의 열쇠가 남는다는 뜻이다. 기계를 남에게 넘기려고 초기화하는
사람에게는 틀린 동작이다.

이 문서는 앞의 약속을 지키고, 뒤의 경우는 별개의 동작으로 남긴다. 하는
방법은 카드 리더로 `/boot/authorized_keys` 를 지우는 것이고, 그건 §7 과
같이 읽어야 한다.

## 7. 공장 초기화는 지우는 것이 아니다

**블록은 그대로 있다.**

공장 초기화는 파일 시스템을 다시 쓴다. 예전 파일이 있던 블록은 할당되지
않은 채로 남아 있고, 그 위에 무언가가 쓰이기 전까지는 읽을 수 있다.
플래시에서는 더하다 — SSD 든 SD 카드든 컨트롤러가 웨어 레벨링을 하므로,
같은 LBA 에 덮어써도 실제 셀은 다른 곳이고 원래 셀은 회수될 때까지
남는다.

그러니 화면은 "지웁니다"라고 말하되 **"복구할 수 없게 만듭니다"라고
말하지 않는다.**

요구사항이 정말 그것이라면 필요한 것은 다음 셋 중 하나이고, **셋 다 지금
없다.**

| 방법 | 지금 상태 |
|---|---|
| 드라이브 자체의 소거 (ATA Security Erase, NVMe Format SES=1 / Sanitize) | 그 ioctl 을 부르는 프로그램이 없다. 파일 시스템 동작이 아니라 드라이브 명령이다 |
| 파티션 전체를 덮어쓰기 | `dd if=/dev/zero` 로 지금도 된다. 디스크 크기만큼 걸리고, **플래시에서는 그래도 부족하다** |
| 처음부터 암호화하고 키를 버리기 | 디스크 암호화가 없다. `CONFIG_MD=n` 이라 device-mapper 자체가 없고, dm-crypt 도 LUKS 도 들어갈 자리가 없다 |

셋째가 유일하게 옳은 답이다. **"지운다"가 한 디스크가 아니라 한 키의
문제가 되는 것**이 이 요구사항의 실제 해법이고, 그건 초기화 화면이 아니라
설치 시점의 결정이다. 커널 설정을 바꾸는 일이므로 이 문서가 정하지
않는다.

## 8. 전원이 중간에 나갔을 때

아무도 계획하지 않는 경우이고, 두 기계에서 답이 다르다.

### 8-1. 규칙 하나

> **되돌리는 일은 몇 번을 다시 해도 같은 결과여야 하고, "끝났다"는 표시는
> 마지막에 지운다.**

이 프로젝트에 이미 두 번 있는 모양이다. `update` 는 새 이미지를 다른
이름에 쓰고, 거기서 검증하고, 그 다음에 부팅하는 이름 위로 rename 한다 —
rename 전의 정전은 옛 시스템을 그대로 두고, 후의 정전은 새 것을 남긴다.
`bootcount` 는 5분을 못 버틴 부팅을 세고, 다섯 번이면 `rc.local` 을
건너뛴다.

### 8-2. 데스크탑

| 언제 | 기계 상태 | 무엇이 구해 주나 |
|---|---|---|
| 표식을 쓰기 전 | 아무 일도 없었다 | — |
| 표식을 쓴 뒤, dd 도중 | 루트가 반쯤 쓰였다. **부팅하면 뜬다** — `preinit` 은 `LPROOT` 를 찾아 마운트하는 데 성공한다 | **표식.** `preinit` 이 표식을 보고 처음부터 다시 dd 한다 |
| dd 가 끝나고 표식을 지우기 전 | 루트는 온전하다 | 같은 표식. 한 번 더 dd 한다. 시간만 든다 |
| 표식을 지운 뒤 | 끝났다 | — |

**두 번째 줄이 표식이 없으면 최악인 경우다.** 반은 옛 시스템이고 반은
새 시스템인 루트는 **부팅한다.** 부팅해서 이상하게 동작한다. 진단하기
가장 어려운 상태이고, 초기화를 한 사람은 자기가 방금 초기화했으니
멀쩡할 거라고 믿는다.

dd 는 같은 오프셋에 같은 바이트를 쓰므로 처음부터 다시 하는 것이
안전하다. 표식을 마지막에 지우는 것 하나가, 되돌릴 수 없는 상태를
"초기화가 두 배 걸린다"로 바꾼다.

**표식은 `LPBASE` 위에 둔다.** ext4 라 저널이 있다. `/boot` 는 FAT 이라
저널이 없고, 정전 뒤에 믿을 수 있어야 하는 것이 이 파일의 존재 이유
전부다. 평소 읽기 전용인 파티션을 두 번의 쓰기 동안만 여는 값을 치를
만하다.

어느 창으로도 못 넘기는 것 하나: **ESP 나 `LPBASE` 자체가 그 순간 망가진
경우.** 커널이 ESP 에 있으므로 앞엣것은 부팅 자체가 안 되고, 카드 리더나
USB 로 다시 굽는 것 말고 길이 없다. 이건 초기화가 만든 창이 아니라 모든
부팅이 이미 가진 창이다.

### 8-3. 램 루트 보드

거의 공짜다. **시스템이 디스크에 없기 때문이다.**

`mke2fs` 도중에 전원이 나가면 데이터 파티션이 반쯤 만들어진 상태로 남고,
다음 부팅에서 `rc` 의 `fsck` 가 preen 모드로 붙어 고칠 수 있으면 고치고,
못 고치면 마운트가 실패한다. 그러면 이렇게 말한다.

> `[rc]   no data partition - continuing in RAM`

**그리고 보드는 뜬다.** 루트가 램에 있고, 셸이 있고, SSH 가 있고,
인증 키는 `/boot` 와 커널 이미지에서 온다. 사람이 들어와서
`datadisk --format` 이나 초기화를 다시 하면 된다.

`/boot` 위의 표식이 아직 지워지지 않았다면 다음 부팅이 알아서 다시
지운다. **이미 지운 파티션을 다시 지우는 것은 아무 해가 없다** — 지우는
일이 멱등이라는 것이 이 보드에서 공장 초기화가 거의 아무것도 아닌 이유
그 자체다.

## 9. 아직 정하지 않은 것

- [ ] 데스크탑 원본을 어디에 둘지 — §4-2 의 A(세 번째 파티션)를 권하지만
      정해진 것이 아니다. 설치 관리자를 먼저 쓰기로 하면 B 가 A 를 포함
      하면서 온다
- [ ] `LPBASE` 파티션 크기. 기본 시스템이 아직 데스크탑이 아니라서 숫자를
      정할 수 없다. Firefox 를 기본 탑재로 유지하는지가 이 숫자의 절반이다
- [ ] 데스크탑의 시스템 업데이트. 시스템이 파일 하나가 아니게 되면서
      `update` 의 전제가 깨졌고, 그것과 공장 초기화는 같은 설계에서
      나와야 한다
- [ ] `웹` 초기화가 브라우저 프로필을 직접 편집할지, 브라우저에게 시킬지
- [ ] 파이의 명령 이름 — `datadisk --factory` 를 권하지만 `reset` 이
      터미널 명령이라는 것 말고는 정해진 게 없다
- [ ] `authkey new` / `add` 가 `/boot/authorized_keys` 에도 쓰게 할지
      (§6-2). 쓰게 하면 초기화 쪽에서 할 일이 없어진다
- [ ] 기계를 남에게 넘길 때의 동작 — 인증 키까지 지우는 별도 경로를 둘지,
      카드 리더로 하라고 안내할지 (§6-3)
- [ ] 초기화 진행을 부팅 화면에서 어떻게 그릴지. `splash` 는 있지만
      진행률을 받는 경로가 없다
- [ ] 초기화가 끝난 뒤 첫 화면. 지금은 "처음 켰을 때와 같은 첫 화면"
      이라고만 적혀 있고, 그 첫 화면이 무엇인지는 아직 어디에도 없다
