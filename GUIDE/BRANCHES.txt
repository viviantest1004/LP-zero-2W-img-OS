SHORT ANSWER
------------
Everything is on main. The other branch is where that work was
done, and it currently points at the same commit.


main
----
The branch you want. It holds:

  - the complete source: kernel config, C library, init, shell,
    all 103 commands, image tools and tests
  - GUIDE/USAGE.txt      how to run it, log in, and build it
  - GUIDE/BRANCHES.txt   this file
  - README.md            the long description, in Korean
  - dist/                prebuilt images, ready to burn or attach:
                           linux-LP_amd64.img.xz
                           test_a_123_LPzero2W_linux.img.xz
                           test_a_123_LPzero2W_linux-utm.zip
                           SHA256SUMS.txt

Start with GUIDE/USAGE.txt.


claude/hohho-xvzof5
-------------------
The development branch. All of the work described above was
committed here and then merged into main, so right now the two
branches contain exactly the same files.

It is kept because it carries the commit history: 71 commits with
messages explaining why each change was made, which is the part
that does not survive a squash. If you want to know why something
is the way it is, read the log here.

Recent work on it, newest first:

  - Every lp_log message was a continuation record, so no reader
    ever saw it. A kmsg write that does not end in a newline is a
    continuation: the kernel leaves the record unfinalised and
    nothing displays it. Also fixed sleep (33 seconds became 3003),
    top -n, test with spaced numeric operands, and added $! to the
    shell.
  - The self-test learns the difference between broken and not
    present.
  - SSH never worked, and the tests that would have said so did
    not exist.
  - The amd64 image shipped 43MB of ARM, and nothing was looking.

Do not commit new work directly to main. Branch, build, run
tests/selftest.sh, then merge.


WHAT IS NOT IN GIT
------------------
Deliberately, because it is all regenerated by a build:

  blobs/      Broadcom GPU firmware  (tools/fetch-blobs.sh)
  sdcard/     assembled card images  (tools/mksdcard.sh)
  keys/       update signing keys - the private key must never
              leave your machine
  build/ .build/ sdk/ repo/   build working directories

dist/ is normally in this list too. The images there are checked
in as a convenience so that somebody can download and run the
system without building it first; they are still reproducible
with ./tools/mkdist.sh.


STATUS
------
Done and verified: the amd64 image passes all 51 checks in
tests/selftest.sh, on real boots in QEMU.

Not done, and deliberately so: two items from the original plan
remain, both from the bare-metal firmware phase that predates the
decision to run a real Linux kernel.

  Phase 2  exception vectors and a panic handler
  Phase 3  SD/eMMC driver, FAT32, bootloader

The system now boots through UEFI with our own Linux kernel, so
neither is on the path anything currently takes. They are open
questions, not missing pieces.

  - SSH 는 한 번도 된 적이 없었고, 그걸 알려줄 테스트도 없었다.

새 작업을 main 에 직접 커밋하지 마세요. 브랜치를 따고, 빌드하고,
tests/selftest.sh 를 돌린 뒤에 합치세요.


깃에 없는 것
------------
전부 빌드로 다시 만들어지는 것들이라 일부러 뺐습니다.

  blobs/      Broadcom GPU 펌웨어  (tools/fetch-blobs.sh)
  sdcard/     조립된 카드 이미지   (tools/mksdcard.sh)
  keys/       업데이트 서명 키. 개인키는 절대 본인 컴퓨터를
              벗어나면 안 됩니다
  build/ .build/ sdk/ repo/   빌드 작업 디렉터리

dist/ 도 원래는 이 목록에 있습니다. 빌드하지 않고도 받아서 바로
돌려볼 수 있도록 편의상 이미지를 넣어둔 것이고, ./tools/mkdist.sh
로 언제든 똑같이 다시 만들 수 있습니다.


현재 상태
---------
끝나고 확인된 것: amd64 이미지가 QEMU 실제 부팅에서
tests/selftest.sh 의 51개 검사를 전부 통과합니다.

일부러 안 한 것: 원래 계획에서 두 항목이 남아 있습니다. 둘 다
진짜 리눅스 커널을 쓰기로 정하기 전의 베어메탈 펌웨어 단계입니다.

  Phase 2  예외 벡터와 패닉 핸들러
  Phase 3  SD/eMMC 드라이버, FAT32, 부트로더

지금은 UEFI 로 자체 리눅스 커널을 띄우기 때문에 둘 다 실제 부팅
경로에 없습니다. 빠진 조각이 아니라 열려 있는 선택지입니다.
