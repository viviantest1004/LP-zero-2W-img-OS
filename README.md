# LP-zero / linux-LP

**English → [README.en.md](README.en.md)**

### ⬇ [이미지 다운로드](https://viviantest1004.github.io/LP-zero-2W-img-OS/)

받을 이미지를 고르고 받은 뒤에 뭘 하는지가 한 페이지에 있습니다.
페이지가 안 열리면 [`dist/`](dist/) 폴더에서 그대로 받으셔도 됩니다.

---

**아무것도 없는 데서 쓴 리눅스 배포판입니다.** C 라이브러리도, init 도,
셸도, 부트로더도 자체 구현이고 명령어가 130개입니다. busybox 도, 그
아래의 glibc 도, 다른 데서 가져온 유저랜드도 없습니다. 시스템 전체가
커널 이미지 파일 하나이고 부팅할 때 램으로 풀립니다.

시작은 **라즈베리파이 제로 2 W** 였습니다. 램이 512MB 인데 우분투를
올리면 아무것도 하기 전에 절반이 사라집니다. 만들다 보니 그 보드에만
매인 구석이 없어서, 지금은 **arm64 가상머신과 일반 amd64 PC 에서도**
그대로 돕니다.

| | |
|---|---|
| 시스템 전체 | 커널 + 유저랜드 파일 **하나**, 13~22MB |
| 부팅 후 남는 램 | 512MB 보드에서 **약 480MB** |
| 부팅 시간 | 전원 인가 후 프롬프트까지 10초 남짓 |
| 명령어 | **130개**, 전부 여기서 쓴 것 |
| SSH | **기본 내장**, 공개키 전용 — `authkey new` 하나면 키를 만들고 접속 명령줄까지 출력 |
| 텍스트 도구 | `sed` `awk` `grep` `diff` — 정규식 엔진 하나를 공유 |
| 패키지 | 자체 `pkg`, 그리고 `apt` — 진짜 데비안 패키지 |
| 서버 | `httpd`, `netstat`, 그리고 init 이 지키는 내 서비스 |
| 파이썬 | CPython 3.12 + pip. manylinux 휠 설치됨 |
| 방화벽 | 기본 켜짐, 포트는 기기에서 바로 엽니다 |
| 라이선스 | MIT |

외부에서 가져온 것은 넷뿐입니다 — 라즈베리파이 GPU 부트롬이 요구하는
Broadcom 블롭, 그리고 암호 구현 셋(dropbear, wpa_supplicant, OpenSSL).
**암호는 직접 만들면 안 되는 물건**입니다.

## 믿고 쓰기 전에

여기 있는 어느 것도 "그러니 쓰지 마세요"가 아닙니다. 전부 "그러니
놀라지 마세요"입니다.

- **지원되는 제품이 아니라 취미로 만든 운영체제입니다.** 보안팀도, CVE
  절차도, 대기하는 사람도 없습니다. 계속 돌아가야만 하는 일에는
  Raspberry Pi OS Lite 나 데비안을 쓰세요.
- **라즈베리파이 실물에서는 검증하지 못했습니다.** 전부 QEMU 에서
  시험했습니다. WiFi 연결, 온도 센서, 하드웨어 워치독, 실제 카드 위에서의
  EMMC 드라이버는 확인되지 않았습니다.
- **보안 부분은 이 저장소 밖의 누구에게도 감사받지 않았습니다.**
  업데이트 서명 검증, 방화벽, DNS·NTP 위조 방지는 전부 구현돼 있고 근거도
  주석에 적혀 있지만, 그것과 검토받은 것은 다릅니다.
- **C 라이브러리가 자체 구현이고 완전하지 않습니다.** 명령어들에 필요한
  만큼 있습니다. 그 밖의 것을 이걸로 컴파일하면 없는 함수를 만날 수
  있습니다. 일반 리눅스 바이너리는 파이썬 옆의 glibc 위에서 그대로
  돕니다.
- **재부팅을 넘겨 남는 곳은 `/data` 하나뿐이고,** 그건 카드 한 장의
  파티션 하나입니다. 카드는 죽습니다.
- **`dd` 를 엉뚱한 장치에 하면 그 장치가 사라집니다.** 여기서 재부팅으로
  되돌릴 수 없는 실수는 이것뿐입니다.
- **GUI 가 없고 컨테이너를 돌리지 않습니다.** DRM 드라이버는 커널에
  있지만 X11 이나 Wayland 는 직접 올려야 하고, cgroup 과 네임스페이스는
  컨테이너 용도로 켜두지 않았습니다.
- **거친 구석은 대개 조용한 쪽입니다.** 최근 한 번에 찾아 고친 것들:
  `echo x | grep x` 가 셸이 존재한 내내 "command not found" 였습니다 —
  파이프의 각 단계를 fork 해서 exec 하는데 echo 는 내장 명령이라 실행할
  파일이 없습니다. `cmd ; echo $?` 는 항상 0이었습니다 — 한 줄이
  실행되기 전에 통째로 파싱되면서 `$?` 도 그때 확장됐기 때문입니다.
  `127.0.0.1` 은 아예 통하지 않았습니다 — 루프백 인터페이스를 아무도
  올리지 않았습니다. apt 는 애초에 동작할 수 없었습니다 — 데비안 베이스
  이미지가 `/etc/resolv.conf` 를 `/run` 안쪽 심볼릭 링크로 넣어두는데,
  그 위에 쓰는 것이 조용히 실패했습니다. 각각 셀프테스트에 검사가
  생겼습니다. 이런 것이 더 나올 거라고 보시는 편이 맞습니다.

**확인된 것**은 이렇습니다. 두 아키텍처의 실제 QEMU 부팅에서
셀프테스트가 실패 없이 통과합니다 — 부팅, 저장소, SSH, 파이썬, 외부
glibc 바이너리, 그래픽, 보안, 오류 경로, 리다이렉션, 로깅, 시간, 새
명령어 전부, 그리고 셸 문법까지. 따로: 포크 폭탄이 한 번의 패스로
정리되고 init·SSH·로그가 살아 있으며, 메모리 고갈은 원인이 된
프로세스만 죽이고, `apt` 가 데비안 패키지를 받아 설치하고 실행합니다.

## SSH 로 들어가기

SSH 서버는 처음부터 들어 있고 자동으로 뜹니다. **비밀번호 인증은 아예
컴파일하지 않았습니다** — 인터넷에 물린 보드에서 비밀번호는 시간
문제라서 선택지로 두지 않았습니다.

전에는 그 때문에 갓 구운 카드에 아무도 들어갈 수 없었고, 키를 넣는
유일한 방법이 카드 리더였습니다. 이제는:

```
authkey new
```

기기에서 키 쌍을 만들고, 공개키를 등록하고, 개인키를 가져갈 수 있는
자리에 두고, 이 기계의 실제 주소가 들어간 접속 명령줄을 그대로
출력합니다.

이미 쓰던 키를 넣고 싶으면 카드의 첫 번째 파티션이 FAT32 라 어느
컴퓨터에서나 열립니다:

```bash
cat ~/.ssh/id_ed25519.pub >> /media/BOOT/authorized_keys
```

> `/boot/authorized_keys` 가 있는 동안은 그쪽이 원본이고, 기기 안의
> 사본은 부팅할 때 덮어씁니다. 기기에서 관리하려면 `/boot` 에서 그
> 파일을 지우세요. 이렇게 만든 이유는 `/data` 가 통째로 망가져도 카드만
> 뽑으면 키를 다시 넣을 수 있어야 하기 때문입니다.

사용자는 root 하나입니다. 안 될 때는 `authkey -l`,
`service status dropbear`, `firewall status`, `netstat -l`, `logd`.

## 부팅하면 뭘 할 수 있나

### 텍스트와 스크립트

`sed` `awk` `grep` `diff` `sort` `uniq` `cut` `tr` `printf` `xargs`
`head` `tail` `wc` `nl` `rev` `cmp` `seq` `find` `tee` `cat` `more`
`edit`

정규식 엔진 하나를 grep, sed, awk 가 같이 써서 셋에서 패턴의 뜻이
같습니다. `grep` 은 POSIX 를 따릅니다 — `+` 와 `?` 는 보통 문자이고,
`-E` 로 확장 문법, `-F` 로 그냥 문자열 검색입니다.

`edit` 는 제대로 된 에디터입니다 — 검색·치환, 되돌리기·다시하기, 줄
이동, 줄번호, 선택과 붙여넣기, 자동 들여쓰기, 그리고 임시 파일에 쓰고
이름을 바꾸므로 저장이 중간에 실패해도 원본이 온전합니다.

### 셸

파이프, `2>` 와 `2>&1` 을 포함한 리디렉션, `&&` 와 `||`, `if`, `while`,
`for`, `break`, `continue`, 함수, `$(...)` 와 백틱, 변수, 글로브,
백그라운드 작업, `read`, `shift`, `export`.

로그인할 때 프로필을 읽습니다 — `/etc/profile` 다음에 `~/.profile`.
`/root` 는 데이터 파티션에 있으므로 `~/.profile` 은 재부팅을 넘겨
남습니다. 설정은 거기에 두시면 됩니다.

### 서버로 쓰기

```
service add httpd -d /data/www -p 8080
firewall allow 8080
```

`httpd` 는 디렉터리를 HTTP 로 서비스합니다 — 큰 파일 이어받기용 range,
304 응답, 동시 연결 수 제한, 모든 소켓에 읽기 타임아웃. 경로 탈출은
퍼센트 디코딩 전후로 모두 막고, 포트를 연 뒤에 권한을 떨어뜨립니다.

`service add` 를 하면 init 이 지킵니다 — 죽으면 다시 뜨고, 재부팅해도
남고, 메모리가 모자라도 `guard` 가 죽이지 않습니다. 전에는 이게
불가능했습니다: `/etc/services` 가 커널 이미지 안에 있어서 사용자
프로그램은 감시받을 방법이 없었고, 서버로 쓰려면 그게 핵심입니다.

포트 여는 데 더는 카드 리더가 필요 없습니다 — `firewall allow 8080`,
`firewall deny 8080`, `firewall ports`.

`netstat` 은 뭐가 듣고 연결돼 있는지 말하고, `info` 는 이 기계에 대한
모든 것을 한 자리에 보여줍니다 — 버그 신고에 붙일 것도 그것입니다.

### 데비안 패키지

```
apt install ripgrep
apt run rg --version
```

진짜 데비안 apt 이고, `/data/debian` 아래 별도 트리로 들어갑니다. 처음
한 번은 95MB 를 받아 440MB 로 풉니다. 그래서 이미지에 넣지 않았습니다.
거기 설치한 어떤 것도 이 시스템의 명령어를 망가뜨릴 수 없고 — 거기에
들어 있지 않으니까요 — `rm -rf /data/debian` 하면 전부 되돌아갑니다.

### 드라이브

USB 드라이브를 꽂으면 `/media` 아래에 알아서 붙습니다. 재부팅을 넘겨
같은 자리에 두려면 `storage adopt /dev/sdb 사진`. 입양한 드라이브는
장치 이름이 아니라 파일시스템 레이블로 찾으므로 다른 포트에 꽂아도 같은
자리에 옵니다. 나머지는 `disk`, `part`, `datadisk`, `expandfs`, `fsck`,
`dd` 가 합니다.

## 왜 안 죽나

### 루트 파일시스템이 램에 있다

시스템 전체가 커널 이미지 안의 cpio 이고 부팅할 때 램으로 풀립니다.
**디스크 위의 어떤 것도 돌아가는 시스템의 일부가 아닙니다.** 전원을
갑자기 뽑아도 깨질 데가 없고, 뭘 잘못 지워도 재부팅하면 원래대로이며,
업데이트는 파일 하나 교체로 끝납니다.

`/bin` `/lib` `/usr` `/opt` 등은 오버레이입니다 — 읽으면 이미지 것이
보이고 쓰면 `/data` 에 남으므로 `cp mytool /bin/` 이 재부팅을 견딥니다.

### `guard`

메모리, 온도, 전압, CPU, 디스크를 봅니다.

- **포크 폭탄**은 먼저 프로세스 그룹 전체에 SIGSTOP 을 걸고 — 멈춘
  프로세스는 fork 할 수 없으니까요 — 그 다음에 쓸어냅니다. 한 번의
  패스, 실측 2493개입니다. 전에는 한 패스에 만 개 가까이 죽여도 따라잡지
  못했습니다.
- **메모리 고갈**: 제일 큰 프로세스가 갑니다. init, 셸, SSH, 워치독,
  그리고 init 이 지키는 서비스는 절대 건드리지 않습니다.
- **CPU 폭주**: 10초에 경고, 30초에 우선순위 강등. 죽이지는 않습니다 —
  시킨 일일 수도 있으니까요.
- **과열·저전압·디스크 가득 참**: 알려주고, 로그부터 정리합니다.

guard 자체도 init 이 감시합니다. 죽이면 1초 안에 되살아납니다.

### 되돌아올 길을 항상 남긴다

하드웨어 워치독이 멈춘 보드를 재시작합니다. 5분을 못 버틴 부팅이 다섯 번
이어지면 `/data/rc.local` 을 건너뜁니다. 5분을 못 버틴 새 시스템은
이전 것으로 되돌립니다. SSH 키는 세 군데에 있고 그중 하나는 어느 PC 나
쓸 수 있는 FAT 파티션입니다. `fsck` 는 기기 자체에서 `/data` 를
복구하고, `poweroff` 는 전원을 내리기 전에 언마운트합니다.

## 보안

- **비밀번호 인증 없음.** dropbear 를 그 기능 없이 컴파일했습니다.
- **업데이트 서명 검증.** RSA-2048 / PKCS#1 v1.5 / SHA-256. 공개키가
  커널 이미지 안에 있어서 카드를 뽑아도 고칠 수 없습니다. **우회
  옵션은 없습니다.**
- **방화벽 기본 켜짐.** netlink 로 한 트랜잭션에 넣고, 이제는 기기에서
  포트를 열 수 있습니다.
- **DNS·NTP 위조 방지.** 무작위 트랜잭션 ID, connect 한 소켓, 질문
  섹션 대조. 논스·모드·stratum 검증.
- **`/data` 는 nosuid,nodev** 이고 외장 드라이브도 같습니다.
- **`defend`** 는 인터넷에 물린 작은 보드에서 실제로 일어나는 것을
  봅니다 — 한 주소에서 반복되는 SSH 실패, 있으면 안 될 자리의 setuid·
  전체쓰기 파일, 전에 없던 리스너, 로그인할 수 있는 키의 변화.
  **백신이 아닙니다** — 시그니처 데이터베이스는 수십 MB 이고 매일
  갱신돼야 하는데, 이 시스템 전체가 13~22MB 입니다.
- **로그인 기록**은 `/data/log/auth`, `integrity` 는 재부팅을 넘겨
  살아남는 파일들의 해시를 확인합니다.

이 중 어느 것도 감사받지 않았습니다.
[믿고 쓰기 전에](#믿고-쓰기-전에) 를 같이 보세요.

## 직접 빌드하기

```bash
sudo apt install clang lld llvm gcc-aarch64-linux-gnu \
     mtools dosfstools e2fsprogs xz-utils zip cpio bc \
     bsdextrautils qemu-system-arm qemu-system-x86 python3

./tools/fetch-kernel.sh && ./tools/fetch-blobs.sh
make && make kernel && make sdcard-linux      # arm64
./tools/mkdist.sh                             # 배포본 세 개
./tests/selftest.sh                           # 기기 안에서
```

체크섬과 다운로드 페이지는 실제 파일에서 만들어집니다. `mkrootfs` 는
소스보다 오래된 바이너리가 들어간 이미지를 거부합니다 — 실제로 한 번
그렇게 나갔고, 이미 맞는 코드를 두고 셀프테스트가 실패했습니다.

`arm64/` 나 `amd64/` 폴더는 없습니다. 두 아키텍처가 같은 소스를 쓰고,
실제로 다른 것은 셋뿐입니다 — 시스템 콜 번호, `crt0.S` 의 진입점, 커널
설정. 복사해서 나눠두면 한쪽만 고치는 사고가 나고, 여기서 두 번
겪었습니다.

자세한 것은 [`GUIDE/USAGE.txt`](GUIDE/USAGE.txt) 에 한국어와 영어로 같이
있습니다.
