# LP-zero 로드맵

라즈베리파이 제로 2 W 위에서 펌웨어부터 OS 까지 직접 만든다.

## 원칙

**직접 못 만드는 것만 다운로드한다.** 그 목록은 딱 셋이다:

| 항목 | 왜 | 크기 |
|---|---|---|
| `bootcode.bin`, `start.elf`, `fixup.dat` | BCM2710 은 GPU 가 먼저 부팅한다. 실리콘 부트ROM 이 요구하는 Broadcom 클로즈드 블롭 | ~3MB |
| `brcmfmac43430-sdio.bin` + nvram | WiFi/BT 칩(CYW43438) 내부로 업로드되는 펌웨어 | ~400KB |
| Linux 커널 소스 | 커널 자체는 직접 쓰지 않는다. **config·디바이스트리·드라이버·패치를 우리가 쓴다** | — |

나머지는 전부 이 저장소의 코드다.

## 단계

### Phase 1 — 베어메탈 펌웨어 + 화면 출력 ✅ 완료

GPU 가 ARM 을 `0x80000` 으로 던진 순간부터의 모든 것.

- `boot.S` — 코어 파킹, EL3/EL2 → EL1 강하, 스택, BSS
- `mmio.h` — 배리어를 동반한 MMIO 접근
- `gpio.c` — 기능 선택, 풀업/풀다운, 입출력
- `uart.c` — PL011 UART0 폴링 드라이버 (115200 8N1)
- `mbox.c` — VideoCore 메일박스 프로퍼티 인터페이스
- `timer.c` — 1MHz 시스템 타이머
- `printf.c` — libc 없는 최소 printf
- `board.c` — 리비전 코드 해석, 워치독 재부팅
- `main.c` — 시스템 정보 덤프 + 대화형 시리얼 모니터

- `fb.c` — 메일박스 프레임버퍼 할당, 픽셀/사각형 그리기
- `console.c` — 프레임버퍼 텍스트 콘솔 (스크롤, 확대 글씨)
- `font_8x16.c` — 비트맵 폰트 (`tools/mkfont.py` 가 TTF 에서 생성)
- `splash.h` — 부팅 화면 문구 (여기만 고치면 된다)

결과물: **20KB `kernel8.img`**. QEMU `raspi3ap` 에서 부팅·화면 출력 검증 완료.

### Phase 2 — 인터럽트 · MMU

- 예외 벡터 테이블 (동기 예외/IRQ/FIQ/SError × 4 EL)
- BCM2710 인터럽트 컨트롤러 + ARM generic timer
- MMU/캐시는 **리눅스를 올릴 계획이면 급하지 않다.** arm64 부팅 규약
  (`Documentation/arm64/booting.rst`)이 커널 진입 시 MMU 가 꺼져 있을 것을
  요구하고, 리눅스는 자기 페이지 테이블을 직접 만든다. 우리 펌웨어에서
  캐시가 의미 있는 것은 SD 에서 커널을 읽는 일회성 구간 정도다.

### Phase 3 — SD/EMMC + FAT32 + 자체 부트로더

> 순서 참고: 리눅스는 우리 부트로더 없이도 `start.elf` 가 직접 올릴 수
> 있다. 커스텀 부트로더와 커스텀 유저랜드를 동시에 디버깅하지 않도록
> **커널·유저랜드를 먼저 띄우고 이 단계를 나중에 끼워넣는다.**


- EMMC 컨트롤러 드라이버 (SD 초기화 시퀀스, CMD/ACMD)
- MBR 파싱 + FAT32 읽기
- 커널 이미지 + 디바이스트리 로드, FDT 셋업 후 Linux 로 점프

여기까지가 "우리가 만든 펌웨어가 리눅스를 부팅시킨다" 지점이다.

### Phase 4 — 커스텀 리눅스 커널

- Cortex-A53 전용 최소 config (불필요 드라이버 전부 제거)
- 자체 디바이스트리
- initramfs 내장, 압축 최적화
- 목표: 부팅 3~8초, idle RAM 20~40MB

### Phase 5 — 커스텀 OS 유저랜드 ✅ 기반 완료

외부 libc 없이 `_start` 부터 전부 직접 작성했다.

- 자체 libc — AArch64 시스템콜 직접 호출, crt0, string, stdio, malloc
- 자체 `init` (PID 1) — 가상 파일시스템 마운트, 셸 감시·재시작, 좀비 수거
- 자체 셸 — 내장 명령, PATH 탐색, 리다이렉션(`< > >>`), 파이프(`|`)
- `cat`, `ls`

**initramfs.cpio.gz = 7,693 바이트.** chroot 통합 테스트 통과.
자세한 내용은 [유저랜드 문서](04-userland.md).

남은 것: 유틸리티 추가, squashfs + overlayfs read-only 루트,
서비스 매니저.

## UI 는 올릴 것인가

올린다. 512MB 라는 제약 때문에 방식이 갈린다:

| 방식 | RAM | 우리 프로젝트 적합성 |
|---|---|---|
| 헤드리스 | 0 | 가장 흔함. SSH/웹으로 제어 |
| **프레임버퍼 직접 그리기** | 수 MB | **★ 채택.** 라이브러리 0개. Phase 1 에서 이미 동작한다 |
| SPI 소형 LCD | 수 MB | 취미 프로젝트 인기. 기존 콘솔 코드 재사용 가능 |
| 풀 데스크탑 (LXDE/Wayland) | 150MB+ | 돌긴 하지만 무겁고, "직접 만든 OS" 와는 거리가 멀다 |

프레임버퍼 콘솔이 이미 동작하므로 그대로 UI 기반이 된다.

폰트는 현재 ASCII(0x20~0x7E) 8x16 만 구워져 있다. 한글을 화면에 띄우려면
16x16 셀 글리프와 UTF-8 디코딩이 추가로 필요하다 (KS X 1001 상용 2350자
기준 약 75KB).

## 최적화 지점 (계속 참조)

- `-mcpu=cortex-a53` — 이 코어 전용 명령어 선택/스케줄링
- **MMU + 캐시 활성화** — 단일 최대 효과. Phase 2 필수
- `--gc-sections` — 안 쓰는 코드 링크 단계에서 제거
- `gpu_mem` 최소화 — GPU 에 준 만큼 ARM 이 잃는다
- 커널 config 에서 미사용 드라이버 제거 — 이미지 크기 + 부팅 시간
- squashfs 압축 루트 — SD 읽기가 병목이라 압축이 오히려 빠르다
- systemd 대신 자체 init — 프로세스 60~90개 → 5~15개
