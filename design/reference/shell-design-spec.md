# 셸 디자인 명세서

자작 OS의 GUI 셸 설계. 지금까지 정한 것 전부.

---

## 0. 프로젝트 전제

| 항목 | 결정 |
|---|---|
| 커널 | 리눅스 (그래픽 드라이버 직접 제작 불필요) |
| 디스플레이 서버 | Wayland, wlroots 기반 자체 컴포지터 |
| 출발점 | tinywl (wlroots 저장소의 최소 컴포지터) |
| amd64 구조 | 디스크 설치형 일반 데스크탑 |
| ARM(파이 Zero 2W) 구조 | 램 라이브 유지, `/data` 영구 |
| 패키지 | apt, pip, pkg 포함 |
| 기본 앱 | 직접 제작하지 않고 `apt`로 설치 (차별화는 셸에서) |

**개발 순서**: QEMU(virtio-gpu) → 실기(RX 580 amdgpu → XPS i915). 엔비디아는 초기 미지원.

## 1. 디자인 시스템

### 1-1. 폰트

| 용도 | 폰트 |
|---|---|
| UI 전체 | Pretendard Variable |
| 터미널/코드 | D2Coding 또는 JetBrains Mono |
| 이모지 | Noto Color Emoji |
| 폴백 | Noto Sans CJK |

**한글 조정값**
- 자간 `-0.01em ~ -0.02em`
- 행간 `1.5~1.6` (라틴은 1.4)
- 크기 라틴 대비 `+1px`

**굵기는 3개만**: Regular 400 / Medium 500 / SemiBold 600

### 1-2. 타입 스케일

| 용도 | 크기 | 굵기 |
|---|---|---|
| 상단바, 라벨 | 13px | 400 |
| 본문, 버튼 | 14px | 400 |
| 목록 제목 | 15px | 500 |
| 창 제목 | 16px | 600 |
| 설정 섹션 제목 | 20px | 600 |

### 1-3. 색 체계

역할별로 고정. 이 밖의 색은 쓰지 않는다.

| 역할 | 쓰임 |
|---|---|
| 앰버 | 한도, 제약, 주의 (방해 금지·비행기·절전 켜짐) |
| 빨강 | 실패, 오류, 데이터 손실 위험 |
| 강조색 | 활성 상태 |
| 회색 5단계 | 나머지 전부 |

**앰버 토큰** (라이트/다크 값을 따로 정의해야 함 — 노랑 계열은 밝은 배경에서 대비가 무너짐)

```
warning-fill     다크 #f0b350   라이트 #8a5a00
warning-bg       다크 #4a3510   라이트 #e5cfa0
warning-surface  다크 #2a2113   라이트 #faf0dc
```

**상태 표현 원칙**: 켜짐/꺼짐은 색이 아니라 **글자 밝기**로 구분한다. 색을 칠하면 화면이 알록달록해지고, 정작 중요한 것을 강조할 색이 남지 않는다. 앰버는 상단바 모드 표시에만.

### 1-4. 시각 요소

- **간격**: 8px 그리드
- **모서리**: 창 10~12px, 버튼/카드 6~8px
- **그림자**: 2겹. `0 1px 2px rgba(0,0,0,.08)` + `0 8px 24px rgba(0,0,0,.12)`
- **테두리**: 0.5px 헤어라인

### 1-5. 모션

**스프링을 쓴다. 베지어가 아니다.**

이유는 중단 가능성. 베지어는 "0.4초 동안 A→B"라는 시간표라 중간에 끊기지만, 스프링은 현재 위치와 속도만 있으면 목표만 바꿔도 자연스럽게 휘어진다. 창을 빠르게 여닫을 때 차이가 결정적이다.

```
매 프레임: 힘 = -강성 × (현재 - 목표) - 감쇠 × 속도
창 애니메이션 기본값: 강성 170, 감쇠 26
```

**시간은 짧게**: 대부분 150~250ms, 큰 동작만 350ms. 500ms 넘기면 하루 쓰고 답답해진다.

**프레임이 우선**: 60fps에서 16.6ms를 넘기면 어떤 곡선을 써도 끊겨 보인다. `wlr_scene`의 damage tracking 필수. 화면 전체를 매 프레임 다시 그리면 파이에서는 즉사.

### 1-6. 문구 말투

`~습니다`체로 통일.

| 상황 | 예시 |
|---|---|
| 상태 알림 | 이미지 파일 내려받기를 마쳤습니다 |
| 제약 안내 | 작업공간은 20개까지 만들 수 있습니다 |
| 오류 | 연결에 실패했습니다. 다시 시도해 주세요 |
| 버튼·항목명 | 설정, 연결, 삭제 (명사·동사 원형) |

**금지**: 시스템이 1인칭을 쓰는 것. `제가 파일을 받았습니다` → `내려받기를 마쳤습니다`

## 2. 상단바

### 2-1. 전체 배치

```
[작업공간 레일] [검색]  ······빈 공간······  [백그라운드 앱] │ [모드] [한] [날짜·시간] [Wi-Fi 볼륨 배터리]
```

| 영역 | 내용 |
|---|---|
| 왼쪽 | 작업공간 레일 → 검색 |
| 중앙 | **비움** (알림·미디어 표시 자리로 예약) |
| 오른쪽 | 트레이 → 모드 → 입력기 → 시계 → 하드웨어 상태 |

**우분투와의 차이**
- 시계를 정중앙에 두지 않는다. 중앙을 비우면 시선이 양 끝으로만 가서 바가 조용해지고, 알림 자리가 확보된다.
- 시계를 오른쪽 그룹에 넣으면 "입력 상태 → 시간 → 하드웨어 상태"가 하나의 정보 덩어리로 읽힌다.

**상태 아이콘 묶음에 알약 배경을 쓰지 않는다.** 윈도우 11의 시각적 서명이다. 평소엔 배경 없이 나란히, 패널이 열렸을 때만 아래에 2px 밑줄.

### 2-2. 작업공간 레일

점이나 알약 대신 **고정 폭 레일 + 미끄러지는 표식**. 스크롤바와 같은 원리.

| 개수 | 표시 |
|---|---|
| 1개 | 표시 없음 |
| 2~10개 | 레일 + 표식 (폭이 개수에 비례) |
| 11~20개 | 레일 + 표식 + 숫자 |
| 20개 | 상한 |

**핵심 장점**: 레일 폭이 32px로 고정이라 작업공간이 몇 개든 레이아웃이 흔들리지 않는다. 우분투의 점 방식은 개수만큼 옆으로 길어져서 오른쪽 요소를 밀어낸다.

**세부**
- 표식 최소 폭 4px (그 이하로는 안 보임)
- 숫자 자리는 처음부터 16px 확보하고 투명도만 바꾼다 (나타날 때 옆 요소가 밀리면 안 됨)
- 빠르게 넘길 때 지나온 구간에 잔상. 속도에 비례해 길어지고 0.2초 안에 사라진다. 4px 표식은 순간이동처럼 보여서 방향 감각이 필요하다
- 이동은 스프링, 드래그로 전환, 클릭하면 오버뷰

**21번째 시도 시**
1. 레일이 0.3초 앰버로 물들고 좌우로 살짝 흔들림
2. 3번 연속 시도하면 레일 아래에 말풍선: `작업공간은 20개까지 만들 수 있습니다`
3. 한 번 본 뒤에는 다시 뜨지 않음

### 2-3. 백그라운드 앱 (트레이)

3개까지 표시하고 4개째부터 `+N`으로 접는다. 앱이 10개여도 바 폭은 그대로. 클릭하면 아래로 펼쳐진다.

### 2-4. 모드 표시

방해 금지·비행기·절전이 켜져 있으면 앰버 아이콘으로 한 덩어리에 표시. 색이 하나라 아이콘이 3개여도 산만하지 않고, "제한이 걸려 있다"가 한눈에 읽힌다.

특히 방해 금지는 켜둔 걸 잊고 "왜 알림이 안 오지?" 하는 상황이 흔하므로 반드시 표시한다.

## 3. 퀵메뉴

### 3-1. 크기와 위치

| 항목 | 값 |
|---|---|
| 폭 | **320px 고정** (비율 아님) |
| 높이 | 약 210px |
| 정렬 | 상태 아이콘 기준 오른쪽 |
| 여백 | 화면 우측 8px, 상단바 아래 6px |

**비율 고정을 쓰지 않는 이유**: 30%로 잡으면 4K에서 1152px이 된다. 내용은 슬라이더 2개와 행 4개뿐인데 그릇만 커진다. 반대로 1280 화면에서는 384px로 오히려 커져서 더 많이 가린다. 내용에 필요한 폭은 글자 크기가 정하고, 글자는 화면 크기에 따라 커지지 않는다.

**보정 두 가지**
- HiDPI 배율 반영: 200% 배율이면 물리 640px로 그려져 눈에는 FHD와 같은 크기
- 하한: `min(320px, 90vw)`

### 3-2. 구성

```
[볼륨 슬라이더]
[밝기 슬라이더]
─────────────
Wi-Fi            iptime_ring
블루투스              꺼짐
방해 금지             꺼짐
전원                  성능
─────────────
[절전] [비행기]      [설정] [전원]
```

**타일 그리드를 쓰지 않는 이유**: 윈도우 11과 우분투가 공통으로 쓰는 2열 토글 타일이 두 OS를 닮아 보이게 하는 가장 큰 요소다. 행 방식은 가로가 좁아도 되고, 값(`iptime_ring`)까지 같이 보여줄 수 있어 정보 밀도가 높다.

### 3-3. 상호작용

| 동작 | 결과 |
|---|---|
| 행 왼쪽(이름) 클릭 | 켜기/끄기 |
| 행 오른쪽(값) 클릭 | **제자리에서 아래로 펼침** |
| 하단 아이콘 | 즉시 토글 |

우분투·윈도우는 화살표를 눌러 하위 화면으로 슬라이드하지만, 여기서는 아코디언처럼 펴진다. 뒤로 가기가 필요 없다. 하위 화면으로 넘어가는 것은 목록 맨 아래의 "설정" 항목뿐.

### 3-4. 각 행의 펼침 내용

**Wi-Fi**
- 연결된 네트워크 (체크 표시)
- 주변 네트워크 목록 (신호 세기 아이콘, 잠금 표시)
- `네트워크 설정` →

**블루투스**
- 연결된 기기 (배터리 % 표시)
- 페어링된 기기 (`연결 안 됨` 상태)
- `새 기기 찾기` →

**방해 금지**
- 30분 / 1시간 / 2시간 / 끌 때까지
- `직접 설정` → (아래 3-5 참고)
- 켜져 있으면 값 자리에 남은 시간 표시 (`1시간 22분`)

**전원**
- 절전 — 배터리를 오래 씁니다
- 균형 — 성능과 전력을 함께 맞춥니다
- 성능 — 최대 속도로 동작합니다

> 이름만으로 차이를 알 수 없는 항목에만 설명을 단다. Wi-Fi나 블루투스에는 붙이지 않는다.

### 3-5. 방해 금지 직접 설정

두 방식을 동시에 제공하고 서로 연동한다.

| 입력 | 설명 |
|---|---|
| 지금부터 | `3시간 30분` — "얼마 동안"으로 생각하는 사람용 |
| 종료 시각 | `05:40` — "몇 시까지"로 생각하는 사람용 |
| 매일 반복 | 켜면 그 시간대가 매일 자동 적용 (취침 시간) |

하나를 바꾸면 다른 하나가 자동 계산된다. 하나만 제공하면 나머지 사람이 매번 암산해야 한다.

### 3-6. 비행기 모드가 켜졌을 때

Wi-Fi와 블루투스 행의 값 자리에 `꺼짐`이 아니라 **`비행기 모드`**를 표시한다. 이유를 안 보여주면 계속 켜려고 시도하게 된다.

### 3-7. 전원 메뉴

```
화면 잠금
절전 대기
로그아웃
─────────
다시 시작
시스템 종료
```

## 4. 검색

### 4-1. 위치와 동작

상단바 왼쪽, 작업공간 레일 오른쪽. 평소엔 아이콘과 `검색` 글자만 있고 입력창 테두리가 없어 거의 보이지 않는다.

- 클릭 또는 `Ctrl+Space`
- 결과는 **바 바로 아래로 펼쳐진다. 전체화면을 덮지 않는다**
- `Esc`로 닫기
- 결과가 없으면 패널 자체가 뜨지 않음

### 4-2. 윈도우 8 실패를 피하는 조건

윈도우 8이 망한 것은 전체화면 런처 자체 때문이 아니라 아래 조건을 어겼기 때문이다. 맥 스포트라이트와 GNOME Activities는 같은 구조인데 문제가 없다.

1. **진입점이 화면에 보인다** — 윈도우 8은 왼쪽 아래 모서리에 아무 표시가 없었다
2. **맥락이 유지된다** — 다른 세계로 넘어가는 게 아니라 위에 뜬 것임을 시각적으로 알린다
3. **대안 경로가 있다** — 파일 더블클릭, 터미널로도 앱을 열 수 있다
4. **터치를 강요하지 않는다** — 키보드 타이핑이 주 사용법

### 4-3. 열자마자

최근 쓴 앱 3개만. **전체 앱 목록을 깔지 않는다.** 목록을 보여주면 사람이 눈으로 훑기 시작하고, 그러면 검색이 아니라 런처가 된다.

### 4-4. 일반 검색 결과

앱·파일·설정·작업공간을 **섞어서** 순위대로. 종류별로 구역을 나누지 않는다. 나누면 세로가 길어지고 순위가 종류에 갇힌다. 오른쪽에 종류를 작게 표시.

### 4-5. 명령 실행

`systemctl`, `apt` 등을 입력하면 모드가 전환된다.

- 왼쪽 아이콘이 검색 → 프롬프트 기호(`>`)로 바뀜
- 글꼴이 고정폭으로 바뀜
- 실행 전에 `관리자 권한이 필요합니다` 미리 표시
- `터미널에서 열기` 대안 제공

**셸 기반 OS라는 정체성이 GUI에서 드러나는 지점.** 스포트라이트와 GNOME 검색에는 없다.

### 4-6. 인라인 유틸리티

**공통 규칙**
- 답이 항상 맨 위에 크게
- Enter → 클립보드 복사 (결과를 보려는 게 아니라 쓰려고 검색하는 것)
- 왼쪽 아이콘이 입력 종류에 따라 바뀜 → 뭘 인식했는지 즉시 확인 가능

| 입력 | 결과 |
|---|---|
| `1920*1080` | 2,073,600 + `계산기에서 열기` |
| `15GB in MB` | 15,360 MB + 기준 안내 |
| `0xff` | 10진 255 / 2진 1111 1111 / 8진 377 |
| `chmod 755` | rwxr-xr-x + 소유자·그룹·기타 풀이 |
| `#f0b350` | 아래 4-7 참고 |

**추가 후보** (전부 오프라인 동작)
- `1699000000` → 사람이 읽는 시간 (로그 볼 때)
- `192.168.0.1/24` → 네트워크 대역 계산
- `uuid`, `base64 안녕` → 즉석 생성·인코딩
- `ko hello` → 번역 (네트워크 필요)

**구현**: 입력을 정규식으로 훑어 유틸리티를 판별하고 결과를 맨 위에 꽂는다. 플러그인처럼 추가 가능하게 설계.

### 4-7. 색상 변환

타이핑하는 동안 **입력창 왼쪽 사각형이 실시간으로 그 색이 된다.** `#f0b3`까지만 쳐도 어떤 색인지 보인다.

| 형식 | 쓰임 |
|---|---|
| RGB | 코드에 붙여넣기 |
| HSL | 손으로 조정할 때 (밝기만 올리기) |
| OKLCH | 색조를 바꿔도 밝기가 유지됨 |

각 줄마다 개별 복사 버튼.

**명도 단계 5칸**을 함께 출력한다. 색 하나를 넣으면 라이트/다크 모드용 밝기 변형이 자동으로 나와서, 디자인 토큰 만들 때 바로 쓸 수 있다.

CSS 표준 색 이름 148개(`teal`, `crimson` 등)도 인식.

## 5. 알림

### 5-1. 세 가지를 구분한다

| 종류 | 위치 | 성격 |
|---|---|---|
| 인라인 피드백 | 원인이 된 UI 옆 | 방금 한 동작의 결과, 짧고 자동 소멸 |
| 알림 | 상단바 중앙 아래 | 시스템·앱이 보내는 소식, 알림 센터에 쌓임 |
| 퀵메뉴 | 오른쪽 | 사용자가 연 패널 |

**위치가 곧 출처다.** 어디서 나온 건지 위치만 봐도 알 수 있어야 한다.

### 5-2. 붙는 것들의 정렬 규칙

**원래 요소의 폭을 기준으로, 필요한 만큼만.**

- 왼쪽에서 나온 것 → 왼쪽 정렬, 글자 길이만큼의 폭
- 오른쪽에서 나온 것 → 오른쪽 정렬
- 중앙에서 나온 것 → 중앙

이 규칙 하나로 앞으로 만들 알림·미디어 표시·트레이 메뉴가 모두 일관되게 처리된다.

### 5-3. 알림 카드

앱 이름(500) + 내용(400) 2줄. 왼쪽에 앱 아이콘.

## 6. 설정 앱 — 알림 섹션

퀵메뉴에는 즉시 토글만, 나머지는 설정으로.

- 앱별 허용/차단, 소리, 잠금화면 표시, 미리보기 내용
- 방해 금지 자동 예약 (요일별 시작·종료 시각)
- **전체화면일 때 자동 켜기** — 게임·영상 볼 때. 실제로 가장 유용한 옵션
- 예외 허용 앱 (방해 금지 중에도 통과)
- 긴급 알림은 항상 통과 (배터리 부족, 디스크 가득 참)
- 방해 금지 중 알림을 쌓아둘지 버릴지
