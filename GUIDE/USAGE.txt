WHAT THIS IS
------------
A very small Linux distribution written from scratch: kernel
configuration, C library, init, shell and 103 commands are all our
own code. The kernel image IS the system - the userland is packed
inside it and unpacks into RAM at boot.

  Whole system      one file, 11-23 MB
  RAM left after boot   480 MB free on a 512 MB board
  Boot time         about 10 seconds to a prompt
  Commands          103, all written here
  SSH               built in, public key only
  Python            CPython 3.12 + pip, manylinux wheels work
  Firewall          on by default
  Licence           MIT

Only four things come from outside: the Broadcom GPU blob the
Raspberry Pi boot ROM demands, and three cryptography
implementations (dropbear, wpa_supplicant, OpenSSL). Cryptography
is the one thing you should not write yourself.


WHICH IMAGE DO I WANT
---------------------
Prebuilt images are in the dist/ folder of this branch.

  dist/linux-LP_amd64.img.xz
      A normal PC, or a desktop virtual machine - VMware,
      VirtualBox, QEMU/KVM, Hyper-V. UEFI boot.

  dist/test_a_123_LPzero2W_linux.img.xz
      Raspberry Pi Zero 2 W hardware AND arm64 virtual machines.
      One image does both: it carries the uncompressed kernel the
      Pi's GPU reads and the EFI executable UEFI reads.

  dist/test_a_123_LPzero2W_linux-utm.zip
      arm64 virtual machines only (UTM, UTM SE, QEMU). Smaller,
      because a VM has no use for the GPU firmware.

Check what you downloaded against dist/SHA256SUMS.txt:

  cd dist && sha256sum -c SHA256SUMS.txt


RUN IT ON A RASPBERRY PI ZERO 2 W
---------------------------------
  xz -d < dist/test_a_123_LPzero2W_linux.img.xz \
    | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

Replace /dev/sdX with your card. Put the card in the board and
power it up.


RUN IT IN A VIRTUAL MACHINE
---------------------------
amd64, QEMU:

  xz -d < dist/linux-LP_amd64.img.xz > lp.img
  qemu-system-x86_64 -m 1024 -bios /usr/share/OVMF/OVMF_CODE.fd \
    -drive file=lp.img,format=raw,if=virtio \
    -netdev user,id=n0,hostfwd=tcp::2222-:22 \
    -device virtio-net-pci,netdev=n0 -nographic

arm64, UTM or UTM SE: unzip the -utm.zip and attach the .img
inside it as the disk. UEFI boot, no other setting needed.


LOGGING IN
----------
There is one user: root.

On the screen or serial console you get a prompt straight away.

Over SSH there are no passwords - password authentication is not
compiled in at all, because a password on a board facing the
internet is only a matter of time. Public keys only:

 1. The first partition of the card or image is FAT32, so it
    opens on Windows, macOS and Linux. Put your public key in a
    file called authorized_keys there:

      cat ~/.ssh/id_ed25519.pub >> /media/BOOT/authorized_keys

    While /boot/authorized_keys exists it is the master copy and
    overwrites the one on the device at every boot. That is
    deliberate: if /data is destroyed you can still get in by
    pulling the card and editing this file. Delete it from /boot
    if you would rather manage keys on the device.

 2. Find the address with  ifconfig  on the console. DHCP is
    automatic; for a fixed address write network.conf on the boot
    partition.

 3.  ssh root@192.168.0.42       (or  ssh -p 2222 root@localhost
     with the QEMU line above)

If it will not connect:

  authkey -l                which keys are accepted right now
  service status dropbear
  firewall status
  cat /data/log/auth        login records


WHERE THE SOURCE IS
-------------------
All of it is on this branch. There are no per-architecture source
trees: arm64 and amd64 build from the same code.

  userland/       our C library, init, shell and all 103 commands
    libc/           the C library - no glibc, no musl
    sh/             the shell
    init/           pid 1
    guard/          watchdog: CPU hogs, memory, temperature
    <name>/         one directory per command
    mkrootfs.sh     assembles the root filesystem
  kernel/         kernel config and build script
    lp-zero.config        arm64 (Raspberry Pi)
    lp-zero-amd64.config  amd64 (PC)
    build.sh              builds the kernel with our initramfs in it
  tools/          image assembly, SDK, package builder, QEMU runner
    mkdist.sh       builds all three distribution images
    mksdcard.sh     assembles one card image
    run-qemu.sh     boots it locally
  tests/          selftest.sh - 51 checks, run on the machine
  boot/           what lands on the FAT32 boot partition
  packages/       package definitions
  docs/           design notes
  dist/           the prebuilt images described above

Read README.md at the top of the repository for the long version
(in Korean): what every command does, why it does not fall over,
the security model, and the known limits.


BUILDING IT YOURSELF
--------------------
  sudo apt install clang lld llvm gcc-aarch64-linux-gnu \
       mtools dosfstools e2fsprogs xz-utils zip cpio bc \
       bsdextrautils qemu-system-arm qemu-system-x86 python3

arm64 (Raspberry Pi and arm64 VMs):

  ./tools/fetch-kernel.sh      # Linux source
  ./tools/fetch-blobs.sh       # Raspberry Pi GPU firmware
  make                         # userland
  make kernel                  # kernel + initramfs
  make sdcard-linux            # sdcard/lp-zero.img

amd64 (PC) - native, no cross compiler needed:

  make ARCH=amd64
  ( cd userland && LP_ARCH=amd64 LP_BINDIR=bin-amd64 \
      LP_ROOTFS_DIR=rootfs-amd64 \
      LP_CPIO_NAME=initramfs-amd64.cpio.gz \
      LP_HOSTNAME=linux-lp LP_OS_NAME=linux-LP ./mkrootfs.sh )
  LP_ARCH=amd64 LP_ROOTFS_DIR=rootfs-amd64 ./kernel/build.sh
  LP_ARCH=amd64 LP_ROOTFS_DIR=rootfs-amd64 \
      ./tools/mksdcard.sh --linux --uefi-only

All three distribution images at once:

  ./tools/mkdist.sh            # or: mkdist.sh amd64 | sd | utm

Update signing key (do this once; never put the private key on a
device - keys/ is in .gitignore):

  ./tools/sign-release.sh --new-key
  make
  ./tools/sign-release.sh kernel/out/Image


CHECKING A BUILD
----------------
tests/selftest.sh runs on the machine itself and prints one PASS
or FAIL line per check - boot, storage, SSH, Python, graphics,
security, error paths, redirection, logging, timing, and whether
the watchdog notices a process pinning a core.

  sh /path/to/selftest.sh

51 checks pass on the amd64 image as of this writing.

이게 뭔가
---------
처음부터 직접 만든 아주 작은 리눅스 배포판입니다. 커널 설정,
C 라이브러리, init, 셸, 103개 명령어까지 전부 자체 코드입니다.
커널 이미지 하나가 곧 시스템 전체이고, 유저랜드는 그 안에 들어
있다가 부팅할 때 램으로 풀립니다.

  시스템 전체        파일 하나, 11~23MB
  부팅 후 남는 램    512MB 보드에서 480MB
  부팅 시간          프롬프트까지 10초 남짓
  명령어             103개, 전부 자체 구현
  SSH                기본 내장, 공개키 전용
  파이썬             CPython 3.12 + pip, manylinux 휠 설치됨
  방화벽             기본 켜짐
  라이선스           MIT

외부에서 가져온 것은 네 개뿐입니다. 라즈베리파이 부트롬이 요구하는
Broadcom GPU 블롭, 그리고 암호 구현 세 개(dropbear, wpa_supplicant,
OpenSSL)입니다. 암호는 직접 만들면 안 되는 물건이라 일부러 가져다
썼습니다.


어느 이미지를 받아야 하나
-------------------------
미리 빌드된 이미지는 이 브랜치의 dist/ 폴더에 있습니다.

  dist/linux-LP_amd64.img.xz
      일반 PC, 데스크톱 가상머신(VMware, VirtualBox, QEMU/KVM,
      Hyper-V). UEFI 부팅입니다.

  dist/test_a_123_LPzero2W_linux.img.xz
      라즈베리파이 제로 2 W 실기와 arm64 가상머신 둘 다.
      이미지 하나가 둘을 모두 지원합니다. 파이 GPU가 읽는 압축
      안 된 커널과 UEFI가 읽는 EFI 실행 파일을 둘 다 담았습니다.

  dist/test_a_123_LPzero2W_linux-utm.zip
      arm64 가상머신 전용(UTM, UTM SE, QEMU). GPU 펌웨어가
      필요 없어서 더 작습니다.

받은 파일은 dist/SHA256SUMS.txt 로 확인하세요.

  cd dist && sha256sum -c SHA256SUMS.txt


라즈베리파이 제로 2 W 에서 쓰기
-------------------------------
  xz -d < dist/test_a_123_LPzero2W_linux.img.xz \
    | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

/dev/sdX 는 본인 카드로 바꾸세요. 카드를 보드에 꽂고 전원을 넣으면
됩니다.


가상머신에서 쓰기
-----------------
amd64, QEMU:

  xz -d < dist/linux-LP_amd64.img.xz > lp.img
  qemu-system-x86_64 -m 1024 -bios /usr/share/OVMF/OVMF_CODE.fd \
    -drive file=lp.img,format=raw,if=virtio \
    -netdev user,id=n0,hostfwd=tcp::2222-:22 \
    -device virtio-net-pci,netdev=n0 -nographic

붙이면 됩니다. UEFI 부팅이고 따로 설정할 것이 없습니다.


로그인
------
사용자는 root 하나입니다.

화면이나 시리얼 콘솔에서는 바로 프롬프트가 나옵니다.

SSH 는 비밀번호가 없습니다. 비밀번호 인증은 아예 컴파일하지
않았습니다. 인터넷에 물린 보드에서 비밀번호는 시간 문제이기
때문입니다. 공개키만 씁니다.

 1. 카드(또는 이미지)의 첫 번째 파티션은 FAT32 라서 윈도우, 맥,
    리눅스 어디서나 열립니다. 거기 authorized_keys 파일에 공개키를
    넣으세요.

      cat ~/.ssh/id_ed25519.pub >> /media/BOOT/authorized_keys

    /boot/authorized_keys 가 있는 동안은 그쪽이 원본이고, 부팅할
    때마다 기기 안의 것을 덮어씁니다. 일부러 그렇게 했습니다.
    /data 가 망가져도 카드만 뽑아서 열쇠를 다시 넣으면 들어갈 수
    있어야 하기 때문입니다. 기기에서 관리하고 싶으면 /boot 에서
    그 파일을 지우세요.

 2. 콘솔에서 ifconfig 로 주소를 확인합니다. DHCP 는 자동입니다.
    고정 주소를 쓰려면 부트 파티션에 network.conf 를 두세요.

 3.  ssh root@192.168.0.42     (위 QEMU 설정이면
     ssh -p 2222 root@localhost)

안 될 때:

  authkey -l                지금 허용된 키
  service status dropbear
  firewall status
  cat /data/log/auth        로그인 기록


소스는 어디에 있나
------------------
전부 이 브랜치에 있습니다. 아키텍처별로 소스를 나누지 않았습니다.
arm64 와 amd64 가 같은 코드로 빌드됩니다.

  userland/       자체 C 라이브러리, init, 셸, 103개 명령어
    libc/           C 라이브러리. glibc 도 musl 도 안 씁니다
    sh/             셸
    init/           pid 1
    guard/          워치독. CPU 점유, 메모리, 온도
    <이름>/         명령어 하나당 디렉터리 하나
    mkrootfs.sh     루트 파일시스템 조립
  kernel/         커널 설정과 빌드 스크립트
    lp-zero.config        arm64 (라즈베리파이)
    lp-zero-amd64.config  amd64 (PC)
    build.sh              initramfs 를 넣어 커널을 빌드
  tools/          이미지 조립, SDK, 패키지 빌더, QEMU 실행
    mkdist.sh       배포 이미지 세 개를 한 번에
    mksdcard.sh     카드 이미지 하나 조립
    run-qemu.sh     로컬에서 부팅
  tests/          selftest.sh - 기기에서 도는 51개 검사
  boot/           FAT32 부트 파티션에 들어가는 것
  packages/       패키지 정의
  docs/           설계 메모
  dist/           위에서 설명한 미리 빌드된 이미지

저장소 최상위의 README.md 에 훨씬 자세한 설명이 있습니다. 명령어
하나하나가 무엇을 하는지, 왜 안 죽는지, 보안 모델, 알려진 한계까지
들어 있습니다.


직접 빌드하기
-------------
  sudo apt install clang lld llvm gcc-aarch64-linux-gnu \
       mtools dosfstools e2fsprogs xz-utils zip cpio bc \
       bsdextrautils qemu-system-arm qemu-system-x86 python3

arm64 (라즈베리파이 + arm64 VM):

  ./tools/fetch-kernel.sh      # 리눅스 소스
  ./tools/fetch-blobs.sh       # 라즈베리파이 GPU 펌웨어
  make                         # 유저랜드
  make kernel                  # 커널 + initramfs
  make sdcard-linux            # sdcard/lp-zero.img

amd64 (PC) - 네이티브라 크로스 컴파일러가 필요 없습니다:

  make ARCH=amd64
  ( cd userland && LP_ARCH=amd64 LP_BINDIR=bin-amd64 \
      LP_ROOTFS_DIR=rootfs-amd64 \
      LP_CPIO_NAME=initramfs-amd64.cpio.gz \
      LP_HOSTNAME=linux-lp LP_OS_NAME=linux-LP ./mkrootfs.sh )
  LP_ARCH=amd64 LP_ROOTFS_DIR=rootfs-amd64 ./kernel/build.sh
  LP_ARCH=amd64 LP_ROOTFS_DIR=rootfs-amd64 \
      ./tools/mksdcard.sh --linux --uefi-only

배포본 세 개를 한 번에:

  ./tools/mkdist.sh            # 또는: mkdist.sh amd64 | sd | utm

업데이트 서명 키(한 번만 만들면 됩니다. 개인키는 절대 기기에 넣지
마세요. keys/ 는 .gitignore 에 있습니다):

  ./tools/sign-release.sh --new-key
  make
  ./tools/sign-release.sh kernel/out/Image


빌드 확인하기
-------------
tests/selftest.sh 는 기기 위에서 돌면서 검사마다 PASS 또는 FAIL 을
한 줄씩 찍습니다. 부팅, 저장소, SSH, 파이썬, 그래픽, 보안, 오류
경로, 리다이렉션, 로깅, 시간, 그리고 워치독이 코어를 붙잡은
프로세스를 알아채는지까지 봅니다.

  sh /경로/selftest.sh

이 글을 쓰는 시점에서 amd64 이미지 기준 51개 전부 통과합니다.
